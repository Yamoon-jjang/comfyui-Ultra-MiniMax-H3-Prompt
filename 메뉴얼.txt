ComfyUI에서 Ultra MiniMax H3 Prompt 또는 R2V 노드 전체에 두꺼운 빨간 테두리가 생기고
`잘못된 입력 / 노드가 하나 이상의 입력 값을 거부했습니다.` 같은 안내가 나오면,
단순히 씬 지시어가 비어 있기 때문이 아니라 현재 설정에 실제로 잘못된 입력이나 구조 조건이 있는지 오류 문구를 먼저 확인하십시오.

현재 V3.50에서는 아무 설정도 하지 않은 완전히 빈 Main T2V/R2V 초안을 Queue 자체의 입력 오류로 중단하지 않습니다.
이 경우 노드는 임의의 인물·장면·행동을 만들어 넣지 않고 `h3_prompt` 출력만 조용히 대기시키며, `info`에 `status=waiting_for_content`를 남깁니다.

- Main · T2V: `전체 장면 / 배경`, 명시적 환경 설정, 활성 시간순 진행의 행동/대사 중 실제 생성 내용이 하나라도 있으면 정상 프롬프트를 생성합니다. `걷고 있다`처럼 짧아도 실제 내용이면 정상이며 공백·스페이스·줄바꿈만은 빈 값입니다.
- Main · I2V/L2V/FL2V: 현재 모드에 맞는 이미지가 실제로 연결되어 있으면 `전체 장면 / 배경`이 비어 있어도 실행할 수 있습니다.
- R2V: 유효한 Picture/Video 기반 Reference가 있거나 활성 시간순 진행의 행동/대사가 있으면 `전체 장면 / 배경`이 비어 있어도 Reference 기반으로 실행할 수 있습니다. Picture/Video 없이 Audio만 연결한 Ref2VA는 별도의 계약 오류로 계속 차단합니다.
- Timeline은 필수 기능이 아닙니다. 장면 지시만으로도 실행할 수 있으며, Timeline의 행동/대사는 필요할 때 시간 변화·행동·대사를 추가하는 선택 기능입니다.

따라서 완전히 빈 초안은 빨간 입력 오류가 아니라 `waiting_for_content` 대기 상태이고, 실제 빨간 테두리가 보이면 화면에 표시된 구체적인 오류 원인을 기준으로 확인하십시오.


============================================================
1. 이 노드는 무엇을 하나요?
============================================================

Ultra MiniMax H3 Prompt는 MiniMax H3용 영상 프롬프트를 한 노드에서 구성하는 ComfyUI 커스텀 노드입니다.

이 노드는 LLM, VLM, 이미지 분석 모델을 사용하지 않습니다.
시작 이미지와 마지막 이미지가 연결되어 있는지는 확인하지만, 이미지 픽셀이나 인물의 얼굴·배경·내용을 분석하지 않습니다.

최종 출력은 MiniMax H3 프롬프트의 핵심 구조에 맞춰 구성됩니다.

- integrated_multimodal_description
- overall_soundscape
- 시청자용 배경 음악(non_diegetic_music)

대사가 있으면 H3 화자 ID와 다음 형식도 자동 구성합니다.

- (S1), (S2), (S3)
- <d>[Korean] 원문 대사</d>
- <d>[English] original dialogue</d>
- 여러 사람이 함께 말할 때 (S1,S2) 같은 복합 화자 ID
  (최종 형식 예: `(S1,S2) say together, <d>[Korean] 원문 대사</d>`)

사용자가 S1/S2/S3를 직접 입력할 필요는 없습니다.

중요: 현재 Timeline의 대사 입력은 말하기/보이스오버뿐 아니라 온스크린 노래/가사에도 사용할 수 있습니다. 같은 Turn의 행동이 선택 인물(또는 선택 그룹)의 노래를 명확히 지시하면서 대사도 입력된 경우, 이 노드는 그 내용을 `sings:` 노래/가사로 렌더링합니다. 다만 오프스크린 보이스오버 노래는 MiniMax H3 공식 가이드에서 명확한 전용 marker를 확인하지 못했으므로 계속 차단합니다.

2. 설치 방법
============================================================

1) 같은 이름의 `comfyui-Ultra-MiniMax-H3-Prompt` 폴더가 이미 있다면 ComfyUI를 종료한 뒤 기존 폴더를 먼저 삭제합니다.
   파일을 위에 덮어쓰지 마십시오. 이전 JS가 남으면 언어 표시나 동적 UI가 섞일 수 있습니다.

2) 새 `comfyui-Ultra-MiniMax-H3-Prompt` 폴더 전체를 다음 위치에 복사합니다.

   ComfyUI/custom_nodes/

3) 현재 번역 기능은 별도의 Python 번역 패키지 설치가 필수는 아닙니다.
   내장 Google/MyMemory 경로로 동작하며, deep-translator가 이미 설치된 환경에서는 마지막 호환 fallback으로만 사용할 수 있습니다.

4) ComfyUI를 완전히 재시작합니다.

5) 노드 검색에서 다음 노드를 찾습니다.

   Ultra MiniMax H3 Prompt


============================================================
3. 한국어 / 영어 UI
============================================================

노드의 항목명, 콤보 선택 표시값, 설명, 툴팁은 ComfyUI의 공식 언어 설정을 따릅니다.

ComfyUI에서 언어를 한국어로 설정하면 항목명과 선택값이 모두 한국어로 표시되고,
영어로 설정하면 항목명과 선택값이 모두 영어로 표시됩니다.
예를 들어 한국어 UI의 `인물 1`, `자동 · 한국어→영어 / 영어는 그대로`는
영어 UI에서 `Person 1`, `Auto · Korean→English / keep English`로 함께 바뀝니다.

이 노드는 브라우저나 Windows 언어를 별도로 추측해 강제로 한국어로 바꾸지 않습니다.
ComfyUI 자체의 언어 설정이 기준입니다.

`전체 장면 / 배경`의 마우스오버 도움말도 현재 ComfyUI 언어를 따릅니다.
한국어 UI에서는 한국어 설명과 실제 입력 예가 보이고, 영어 UI에서는 같은 의미의 영어 설명과 예가 보입니다.
노드 메타데이터 툴팁은 런타임에서도 현재 언어에 맞춰 동기화됩니다.

워크플로우 내부에 저장되는 실제 옵션 값은 A, ko_to_en, on_screen 같은 고정 내부값(canonical)을 사용합니다.
화면 표시만 현재 언어로 바뀌므로 UI가 한국어/영어로 전환되어도 워크플로우의 의미와 실행값은 바뀌지 않습니다.


============================================================
4. 가장 쉬운 사용 순서
============================================================

처음 사용할 때는 다음 순서만 기억하면 됩니다.

[현재 초기 화면을 먼저 확인]
- Main과 R2V 모두 새 노드/설정 초기화 직후는 기본 보기입니다. 이때 하단 버튼에는 `전체 설정 보기`가 표시됩니다. `기본 보기` 버튼이 보이면 현재는 전체 설정 보기 모드입니다. 그룹의 `▶/▼` 상태는 별개입니다.
- 새 그룹 UI의 공통 기본 구조는 `전체 장면 / 배경`(항상 표시) → `▶ 기본 설정` → `▶ 촬영 설정` → `▶ 사운드` → `▶ 인물 1` → `▶ 진행 1` 입니다. 새 노드와 초기화 직후에는 모두 접혀 있으며 각 헤더를 클릭해 `▼`로 펼쳐야 내부 행이 보입니다. R2V는 `전체 장면 / 배경` 바로 아래에 연결된 Reference 그룹이 추가될 수 있고, `기본 설정`의 영상 입력 방식은 `R2V Reference (고정)`으로 표시됩니다.
- R2V의 `영상 입력 방식 : R2V Reference (고정)`은 화면 정렬/설명용 한 줄이며 backend나 프롬프트에 전달되지 않습니다. 실제 R2V 동작은 Picture/Video/Audio Reference와 Reference 역할 설정으로 결정됩니다.
- R2V Reference를 연결하면 `전체 장면 / 배경` 바로 아래에 `▼ 이미지/영상/오디오 참조 N` 그룹이 추가됩니다. 그 안에 Reference 세부 설정이 들어가며, 이후 `기본 설정 → 촬영 설정 → 사운드 → 인물 N → 진행 N` 그룹 흐름이 이어집니다.
- `설정 초기화`는 resettable widget의 외부 STRING 연결을 해제하지만 Main의 시작/마지막 이미지와 R2V의 Picture/Video/Audio Reference 미디어 선은 유지합니다. R2V Reference 역할/내용 UI 설정은 기본값으로 돌아갑니다.
- 예제에서 어떤 하위 메뉴가 보이지 않으면 무작정 찾지 말고 먼저 `주요 인물 수`, `시간순 진행 수`, `여러 촬영 컷 사용`, `촬영 컷 N 시작`, `○ 인물 N 고급 설정`을 예제 지시 순서대로 맞추십시오.
- 화면의 실제 토글 표기는 그대로 사용합니다. `여러 촬영 컷 사용`, `참조 이미지 의상 유지` 같은 BOOLEAN은 `ON/OFF`, `○ 인물 N 고급 설정`은 `▶(접힘)/▼(펼침)`입니다. 메뉴얼과 예제의 설정값 표기도 이 화면 문구를 기준으로 합니다.
- 관계된 항목 위에는 **접기/펼치기 그룹 헤더**가 표시됩니다. `기본 설정`은 장면 번역·영상 입력 방식·길이·스타일·주요 인물 수·시간순 진행 수를, `촬영 설정`은 카메라와 촬영 컷을, `사운드`는 환경음과 배경 음악을, `인물 N`은 해당 인물 프로필을, `진행 N`은 해당 시간순 행동·대사를 묶습니다. R2V의 연결된 Reference도 각각 별도 그룹으로 표시됩니다. 헤더에는 현재 값을 읽은 짧은 요약이 표시되며, 헤더에 마우스를 올리면 해당 그룹의 성격을 간략히 설명하는 툴팁이 나옵니다. 요약과 얇은 왼쪽 색상 표식은 화면 표시 전용이며 프롬프트 설정값이 아닙니다. 헤더를 접어도 내부 값은 삭제되지 않으며, 외부 STRING 등이 실제 연결된 위젯은 연결 단자 안정성을 위해 접힌 상태에서도 계속 표시될 수 있습니다. `전체 장면/배경(scene_prompt)` 입력창은 기존 ComfyUI 크기 유지 로직을 보호하기 위해 그룹 접힘 대상이 아닙니다. `설정 초기화`를 확정하면 모든 그룹은 다시 `▶`(접힘) 상태가 됩니다.
- 그룹 헤더의 `▶/▼`와 하단의 `전체 설정 보기 / 기본 보기`는 서로 다른 기능입니다. `▶/▼`는 해당 그룹 자체를 접고 펴며, `기본 보기`는 실제 빠른 편집에 필요한 핵심 행만 남깁니다. 기본 보기에서는 모든 활성 인물의 성별·연령대·민족적 외형, 모든 활성 진행의 대상·시작 시점·행동·대사, 기본 장면/날씨/스타일, 카메라 움직임·촬영 컷 1 대상·구도·`여러 촬영 컷 사용` ON/OFF, 환경음/배경 음악을 사용할 수 있습니다. 유효한 시작 이미지 I2VA에서는 `참조 이미지 의상 유지`도 기본 보기에 표시됩니다. 환경음/배경 음악에서 직접 입력 모드를 고르면 필요한 직접 입력칸도 기본 보기 안에서 즉시 나타납니다. `전체 설정 보기`는 인물 외형·의상·음성 세부, 진행별 장면/날씨 변경·언어·말하는 방식, 촬영 컷 1의 기본 카메라 이동 폭·속도와 촬영 컷 2~6의 전환 방식·개별 카메라 움직임·개별 이동 폭·속도 같은 정밀 제어를 추가합니다. 여러 촬영 컷을 켜면 기본 보기에서도 활성 컷의 시작시점·대상·구도와 바로 다음 컷 ON/OFF가 순서대로 나타납니다. 보기 전환은 값이나 프롬프트를 변경하지 않습니다.
- R2V Reference의 동적 설정 행은 실제 화면 순서대로 `참고할 요소 → (같은 대상 연결 / 대사 화자 지정, 해당 역할에서만) → 반영 방식 → 원본 내용·특징 → 적용 구간(필요한 역할에서만) → 결과 반영 방법` 순서입니다. Reference 미디어를 먼저 연결해야 이 행들이 나타납니다.


[Main · T2V/I2V/L2V/FL2V]
1) I2V/L2V/FL2V라면 시작/마지막 이미지를 먼저 연결합니다. T2V는 연결할 이미지가 없습니다.
2) `전체 장면 / 배경`을 입력합니다.
3) `▶ 기본 설정`을 펼쳐 장면 설명 번역, 영상 입력 방식, 영상 길이, 영상 스타일을 맞춥니다.
4) 이미지 연결로 새로 나타난 참조 이미지 옵션이 있다면 이때 확인합니다.
5) `주요 인물 수`와 `시간순 진행 수`를 맞춘 뒤 인물/진행을 설정합니다.
6) 필요하면 촬영 설정과 사운드를 설정하고 H3 프롬프트 출력을 생성 흐름에 연결합니다. 기본 보기에서는 카메라 움직임/촬영 컷 1 대상·구도와 `여러 촬영 컷 사용` ON/OFF, 환경음/배경 음악을 빠르게 다룹니다. 직접 입력 모드를 선택하면 해당 사운드/음악 입력칸은 기본 보기에서도 바로 나타납니다. 촬영 컷 2~6의 시작시점·대상·구도와 다음 컷 ON/OFF는 기본 보기에서도 순차적으로 설정할 수 있습니다. 촬영 컷 1의 기본 카메라 이동 폭·속도와 각 컷의 전환 방식·개별 카메라 움직임·개별 이동 폭·속도가 필요할 때 전체 설정 보기로 전환합니다.

[R2V · 반드시 이 순서 권장]
1) 사용할 Picture/Video/Audio Reference를 가장 먼저 연결합니다. 연결 직후 `전체 장면 / 배경` 아래에 Reference 그룹이 생기는 것만 확인합니다.
2) `▶ 기본 설정`에서 영상 길이, 영상 스타일, 주요 인물 수, 시간순 진행 수를 먼저 확정합니다. `영상 입력 방식 : R2V Reference (고정)`은 읽기 전용입니다.
3) 여러 Shot을 쓰는 예제라면 기본 보기의 `▶ 촬영 설정`에서 `여러 촬영 컷 사용=ON`을 켭니다. 그러면 촬영 컷 2의 시작 ON/OFF와 핵심 설정이 나타나고, 컷 2를 ON으로 유지하면 바로 다음 촬영 컷 3 ON/OFF가 나타나는 식으로 필요한 Shot 수를 순서대로 확정할 수 있습니다. 시작시점·대상·구도는 기본 보기에서 설정하고, 전환 방식·개별 카메라 움직임·개별 이동 폭·속도가 필요할 때만 `전체 설정 보기`로 전환합니다. Reference의 `적용 구간` 후보는 이 Shot 구조를 따라가므로 이 단계가 Reference 세부 설정보다 먼저입니다.
4) `전체 장면 / 배경`과 장면 설명 번역을 입력합니다. 이 항목은 전체 영상의 공통 기반이므로 인물·Shot·진행 세부값보다 먼저 정하는 것이 가장 이해하기 쉽습니다.
5) 이제 연결로 생긴 각 Reference 그룹을 펼칩니다. 기본 보기에서는 `참고할 요소 → 반영 방식 → 적용 구간`을 정할 수 있고, Audio Reference는 `대사 대상`도 바로 지정할 수 있습니다. 같은 대상 연결, 원본 내용·특징, 결과 반영 방법까지 예제대로 입력하려면 전체 설정 보기에서 나머지 세부 행을 설정합니다.
6) 인물 → 촬영 컷 세부값 → 시간순 진행 → 사운드 순으로 입력합니다.
7) 같은 Reference 파일과 같은 순서를 실제 MiniMax H3 R2V 생성 흐름에도 연결하고 `H3 프롬프트` 출력을 prompt 입력에 연결합니다.

R2V에서는 `Reference 파일 연결`은 가장 먼저 하지만, `Reference 세부 설정`까지 가장 먼저 끝내는 것은 아닙니다. 특히 `적용 구간`에서 Shot 2 이상을 고르는 예제는 반드시 Shot 구조를 먼저 활성화해야 합니다.

------------------------------------------------------------
4-A. 예제 폴더를 먼저 보는 방법
------------------------------------------------------------

배포본의 `예제` 폴더에는 `00_예제_먼저읽기_V3.50.txt`가 있습니다. 처음 사용하는 경우 이 파일부터 읽는 것을 권장합니다.

처음에는 현실적인 예제로 구조를 익히면 각 설정이 영상에서 어떤 역할을 하는지 이해하기 쉽습니다.
권장 시작 예제:
1) `Ultra_MiniMax_H3_V3.50_I2VA_루프탑카페_블루아워커피광고_15초_실전예제.zip`
   - 시작 이미지에 실제로 보이는 인물, 커피잔, 난간, 도시를 그대로 이용해 블루아워 커피 광고를 만듭니다.
2) `Ultra_MiniMax_H3_V3.50_T2VA_해안도로_골든아워자동차광고_15초_실전예제.zip`
   - 차선 유지, S자 코너, 가속과 카메라 추적을 익힙니다.
3) `Ultra_MiniMax_H3_V3.50_T2VA_아침베이커리_크루아상광고_15초_실전예제.zip`
   - 제품을 이미 구운 상태에서 정리 → 글레이즈 → 플레이팅으로 이어지는 현실적인 행동 순서를 익힙니다.
4) `Ultra_MiniMax_H3_V3.50_R2V_네온도시_시간붕괴추격전_15초_실전예제.zip`
   - Reference의 실제 도로·인물·차량 위치를 유지하면서 같은 공간 안에서 행동을 확장하는 방법을 익힙니다.

환상적인 장면을 보고 싶다면 FL2VA의 별빛 망토/사막 거울호수, T2VA의 달빛 조선소/빙하 성당/하늘 정원, R2V의 하늘고래 예제를 이어서 사용할 수 있습니다.

예제 작성과 응용에서 가장 중요한 원칙:
- `전체 장면 / 배경`은 장소, 시간대, 빛, 날씨, 처음 보이는 사물과 인물의 위치처럼 **영상이 시작할 때의 무대**를 적습니다.
- 5초 뒤, 10초 뒤 일어날 사건까지 전체 장면에 미리 몰아넣지 말고 `진행 1 → 진행 2 → 진행 3`에 시간 순서대로 적습니다.
- 이미지/Reference 기반 예제에서는 이미지에 실제로 보이는 공간 관계를 먼저 따릅니다. 멀리 있는 호수나 건물에 손을 대야 한다면 먼저 그곳까지 이동하는 장면이 필요합니다. 15초 안에 이동이 무리라면 멀리서 가능한 행동으로 바꾸는 편이 안정적입니다.
- 행동은 결과만 쓰지 말고 필요한 준비 동작을 포함합니다. 예: `커피를 마신다`보다 `잔을 들어 향을 맡고 → 한 모금 마시고 → 잔을 내린다`처럼 화면에서 보이는 순서로 적습니다.
- 카메라 지시는 행동 문장에 반복해서 섞기보다 `촬영 설정`에서 담당하게 합니다.

여러 촬영 컷 예제의 카메라 옵션:
- 상단 `기본 카메라 움직임`, `카메라 이동 폭`, `카메라 속도`는 촬영 컷 1에 적용됩니다.
- 촬영 컷 2~6은 각각 `촬영 컷 N 카메라 움직임`, `촬영 컷 N 카메라 이동 폭`, `촬영 컷 N 카메라 속도`를 따로 가집니다.
- `기본 설정을 따라감`은 촬영 컷 1의 이동 폭/속도를 이어받습니다.
- `기본 · 생략`은 그 촬영 컷에서 이동 폭 또는 속도 지시만 생략합니다.
- `작게/크게`, `느리게/빠르게`를 고르면 그 촬영 컷에서만 별도로 적용됩니다.
- 배포 예제의 따라하기 문서는 여러 촬영 컷을 쓸 때 이 두 개별 옵션까지 모두 적습니다.

예제에서 항목이 안 보이면 다음 순서를 확인하십시오.
- 먼저 하단의 `전체 설정 보기`로 전환합니다. 각 그룹은 별도로 `▶→▼`로 펼쳐야 합니다.
- Person 2/3은 `주요 인물 수`를 먼저 늘려야 나타납니다.
- 진행 2~6은 `시간순 진행 수`를 먼저 늘려야 나타납니다.
- `여러 촬영 컷 사용`을 켜면 촬영 컷 2가 활성화되고, 이후 촬영 컷 3~6은 각 `촬영 컷 N 시작`을 ON으로 켜서 순서대로 사용할 수 있습니다.
- R2V Reference 세부 행은 실제 Picture/Video/Audio Reference를 연결해야 나타납니다.


------------------------------------------------------------
4-0. I2VA에서 시작 이미지의 의상을 끝까지 유지하고 싶을 때
------------------------------------------------------------

I2VA에서는 `참조 이미지 의상 유지`를 사용할 수 있습니다.

이 항목은 실제 동작 모드가 I2VA이고 시작 이미지가 연결되어 있을 때 `영상 스타일` 아래의 참조 이미지 설정 구역에서 `참조 이미지 유지 강도` 바로 아래에 나타납니다. 자동 모드에서는 시작 이미지만 연결된 경우에 표시되고, 수동 I2VA에서는 마지막 이미지가 추가로 연결되어 있어도 그 마지막 이미지는 모드 판정에서 무시되므로 표시됩니다. 시작 이미지가 없거나 T2VA/L2VA/FL2VA를 명시한 경우에는 숨겨집니다.
기본값은 `ON`입니다.

`ON`:
- 시작 이미지에 보이는 인물의 의상, 색상, 소재, 액세서리를 영상 전체에서 유지하도록 강하게 지시합니다.
- 시간순 진행 수를 1개에서 6개로 바꿔도 이 옵션의 값은 바뀌지 않습니다.
- `여러 촬영 컷 사용`이나 촬영 컷 2~6의 ON/OFF를 바꿔도 다른 설정값은 임의로 지우지 않습니다.
- 인물의 `의상 프리셋`이나 `의상 추가 입력`을 바꿔도 이 옵션은 자동으로 꺼지지 않습니다.
- 켜진 동안 의상 프리셋과 의상 추가 입력은 워크플로우에 그대로 저장되지만, 최종 H3 프롬프트에서 의상을 바꾸는 지시로는 사용하지 않습니다.
- 따라서 의상 추가 입력이 한국어여도 잠금이 켜져 있는 동안에는 그 의상 문장을 번역할 필요가 없어, 참조 의상 유지와 무관한 번역 실패가 발생하지 않도록 했습니다.

`OFF`:
- 시작 이미지 의상 고정 지시를 넣지 않습니다.
- 인물별 의상 프리셋과 의상 추가 입력이 V1.9와 같은 방식으로 다시 정상 적용됩니다.
- 잠금을 켜는 동안 숨겨졌던 의상 설정값을 삭제하지 않았기 때문에 다시 입력할 필요가 없습니다.

중요:
- 이 기능은 I2VA 전용입니다. T2VA, FL2VA, L2VA에서는 표시하지 않으며 실행에도 적용하지 않습니다.
- 시간순 진행의 행동 문장이나 전체 장면 설명에 사용자가 직접 "옷을 갈아입는다" 같은 상반된 지시를 적으면 모델 입장에서는 충돌하는 명령이 될 수 있습니다. 의상을 유지할 목적이라면 이런 문장은 넣지 않는 것이 좋습니다.
- 이 노드는 이미지 픽셀을 분석하지 않습니다. 어떤 옷인지 직접 판독하는 것이 아니라 `<Picture 1>`의 실제 시각 정보를 MiniMax H3가 참조하도록 강하게 고정 지시합니다.

------------------------------------------------------------
4-1. 설정별 빠른 실사용 예
------------------------------------------------------------

아래 예는 "이 칸에 실제로 무엇을 넣어야 하는가"를 빠르게 확인하기 위한 요약입니다.
내부 이름은 워크플로우/코드에서 보이는 이름이고, 괄호 안은 한국어 UI 표시입니다.

scene_prompt (전체 장면 / 배경)
장소, 분위기, 조명, 시간대, 인물들의 초기 배치처럼 영상 전체에 공통으로 유지될 설정을 한 덩어리로 적습니다.
예: 넓은 초원, 늦은 오후의 따뜻한 햇빛, 한 여성과 한 남성이 서로 마주 서 있다.

scene_translate (장면 설명 번역)
대사를 제외한 한국어 설명문을 영어로 자동번역할지 선택합니다. 일반적인 한국어 사용자는 기본값을 그대로 두면 됩니다. 자동에서는 전체 장면 / 배경뿐 아니라 진행 행동, 환경음, 배경 음악, 인물 외형·복장·음성 특징, R2V Reference의 설명·적용 지시어 등 실제 사용되는 비대사 서술의 한국어를 각 안전한 내부 번역 경로로 영어화합니다. `사용 안 함 · 입력 그대로`에서는 이 비대사 서술의 온라인 번역을 모두 건너뛰고 입력을 그대로 유지합니다. 대사는 어느 설정에서도 번역하지 않습니다.
예: `자동 · 한국어→영어 / 영어는 그대로`

mode (영상 입력 방식)
`자동`에서는 시작/마지막 이미지 연결 상태에 따라 H3 모드를 판별합니다. 수동 모드는 사용자가 고른 모드를 우선합니다. 수동 T2VA는 연결 이미지를 무시하고 T2VA로 동작하며, 수동 I2VA는 시작 이미지, L2VA는 마지막 이미지, FL2VA는 시작+마지막 이미지가 필요합니다. 필요한 이미지가 없으면 다른 모드로 자동 변경하지 않고 배지 안내 후 `h3_prompt` 실행만 대기합니다.
예: 자동 + 시작 이미지만 연결 → I2VA, 수동 T2VA + 이미지 연결 → T2VA

duration_seconds (영상 길이)
실제 MiniMax H3 생성 노드의 영상 길이와 같은 정수 초를 입력합니다. 이 노드는 4~30초 정수를 허용합니다. 직접 소수값을 입력해도 가장 가까운 정수 초로 즉시 정규화되며, 예를 들어 `5.0213`은 `5`, `5.50123`은 `6`으로 처리됩니다. 실제 위젯 값, 접힌 `기본 설정` 요약, Queue에 전달되는 값, 최종 프롬프트의 영상 길이는 이 정규화된 정수값을 공통으로 사용합니다. MiniMax H3의 공식 지원 범위는 15초까지이며, 16~30초는 로컬/고급 활용용 확장 범위라 생성 시간과 메모리 사용량이 크게 늘 수 있습니다. Main에서 16초 이상을 선택하면 접힌 `기본 설정` 헤더에도 `⚠ 공식 H3 범위 초과`가 표시되어, 확장 범위를 공식 지원 범위로 오해하지 않도록 합니다.
예: 실제 영상이 10초라면 `10`, 24초라면 `24`

visual_style (영상 스타일)
명시적 스타일을 선택하면 MiniMax H3 권장 구조에 맞춰 `[Shot 1]`의 맨 앞에서 전체 스타일(overall style)을 먼저 선언하며, 이후 촬영 컷과 진행 중 배경 변경에도 같은 스타일이 계속 유지되도록 명시합니다.
스타일은 두 성격을 함께 포함합니다. `실사`, `2D 애니메이션`, `일본 애니메이션풍`, `3D CG`, `점토 스톱모션`, `수채화풍`, `흑백 영화풍`처럼 영상 전체의 렌더링 매체를 바꾸는 항목이 있고, `문명 붕괴 이후 세계풍`, `사이버펑크`, `어두운 고딕풍`, `어두운 판타지풍`처럼 선택한 장소의 세계관·미술 방향 자체를 재해석해야 제대로 보이는 항목이 있습니다. 후자는 장소의 정체성을 없애는 것이 아니라 같은 장소를 해당 세계관으로 보이게 만듭니다.
특히 `문명 붕괴 이후 세계풍`은 단순한 먼지·저채도 색보정이 아니라 실제 post-apocalyptic 세계입니다. 선택한 장소를 알아볼 수 있게 유지하면서 문명 붕괴 뒤의 방치·파손·기능을 잃은 기반시설·잔해·풍화·임시 수리나 수집된 재료 같은 맥락상 가능한 흔적을 장면 전체에 적용합니다. 짧은 영상 안에서 정상 도시가 폐허로 변하는 변신 과정을 만들지는 않습니다.
`2D 애니메이션`은 범용적인 2D 표현이고 `일본 애니메이션풍`은 선화·셀 셰이딩·연출이 더 구체적인 2D 미술 언어입니다. `빈티지 필름풍`은 촬영 시대를 자동으로 과거로 바꾸지 않고 필름 스톡·광학 질감을 바꿉니다.
`자동`은 T2VA에서 임의 스타일을 추측하지 않습니다. I2VA/FL2VA/L2VA에서는 이미지를 분석했다고 가장하지 않고 참조 이미지가 가진 스타일을 유지하라는 중립적인 지시만 사용합니다.
장면 설명에 선택한 프리셋과 명백히 반대되는 미디어 스타일 문구가 있으면 사용자 문구를 몰래 삭제하지 않고 info에 충돌 경고를 표시합니다.
예: 편안한 가족 장면 → `따뜻한 가족 영화풍`, 자연스러운 일상 장면 → `자연스러운 실사풍`, 애니메이션 특유의 셀 표현 → `일본 애니메이션풍`, 문명 붕괴 뒤의 도시 → `문명 붕괴 이후 세계풍`, 네온 기술도시 → `네온 미래 도시풍 (사이버펑크)`

camera_motion (카메라 움직임)
영상 전체에서 사용할 명시적 카메라 움직임이 있을 때 선택합니다.
예: 인물을 따라 이동 → `피사체 따라가기`, 천천히 가까워짐 → `카메라 앞으로 이동`, 카메라 전체가 위로 움직임 → `카메라 수직 상승`

camera_amplitude (카메라 이동 폭)
선택한 카메라 움직임의 변화 폭을 지정합니다. 카메라 움직임이 자동/없음이면 보통 기본값으로 둡니다.
예: 얼굴을 아주 조금만 당겨 보고 싶을 때 `작게`

camera_speed (카메라 속도)
선택한 카메라 움직임의 속도를 지정합니다.
예: 천천히 다가가는 장면 → `느리게`

reference_fidelity (참조 이미지 유지 강도)
`영상 스타일` 바로 아래의 참조 이미지 관련 설정 구역에 표시됩니다. 자동 모드는 실제 연결 상태로 판별하고, 수동 I2VA는 시작 이미지, L2VA는 마지막 이미지, FL2VA는 시작+마지막 이미지가 연결되어 유효한 이미지 모드가 성립할 때 나타납니다. 수동 T2VA는 이미지가 연결되어 있어도 참조 이미지를 프롬프트 모드 판정에서 무시하므로 숨겨집니다. 필요한 참조 이미지가 빠진 수동 이미지 모드에서도 숨겨지며, 숨겨져도 선택한 강도 값은 삭제되지 않고 그대로 보존됩니다.
시작·마지막 참조 상태를 얼마나 강하게 유지할지 정합니다.
예: 얼굴·의상·구도를 최대한 유지하고 싶을 때 `강하게 유지`

참조 이미지 의상 유지
`참조 이미지 유지 강도` 바로 아래에 표시됩니다. 이 옵션은 실제 동작 모드가 I2VA이고 시작 이미지가 연결되어 있을 때 나타납니다. 자동 모드에서는 시작 이미지만 연결되어 I2VA가 된 경우이며, 수동 I2VA에서는 마지막 이미지가 추가로 연결되어 있어도 그 마지막 이미지는 프롬프트 모드 판정에서 무시되므로 I2VA 설정을 유지합니다. 기본값은 `ON`입니다.
켜져 있으면 시작 이미지의 의상·색상·소재·액세서리 유지를 별도로 강조하고, 인물별 의상 프리셋/의상 추가 입력은 저장값은 유지하되 실행 프롬프트의 의상 변경 지시로 사용하지 않습니다. 시간순 진행 수, 촬영 컷 활성 상태, 의상 설정을 바꿔도 이 옵션 자체가 자동으로 켜지거나 꺼지지 않으며, 조건이 맞지 않아 잠시 숨겨져도 사용자가 선택한 값은 보존됩니다.
이 옵션은 MiniMax H3 내부의 별도 의상 잠금 수치를 조절하는 기능이 아니라, `<Picture 1>`의 의상을 영상 전체에서 유지하도록 최종 프롬프트에 명확한 전역 지시를 추가하는 기능입니다. 따라서 실제 유지 정도는 MiniMax H3의 지시 준수 결과에 따라 달라질 수 있습니다.

soundscape_mode (환경음)
주변 소리와 동작 소리의 생성 방식을 정합니다. 대사와 배경 음악은 별도입니다.
예: 카페의 잔잔한 주변음이 필요하면 `자동`, 주변/동작음을 빼고 싶으면 `환경음·동작음 없음`

sound_hint (환경음 직접 입력)
MiniMax H3의 `overall_soundscape` 규칙에 맞춰 주변음, 움직임에서 나는 소리, 비언어적 사람 소리만 적습니다. 실제 대사·보이스오버·배경음악은 이 칸에 넣지 않습니다. 명백한 대사/음악 문구를 넣으면 내용은 임의 삭제하지 않지만 info에 잘못된 필드일 수 있다는 경고가 표시됩니다. 가급적 영어로 입력하고, 한국어라면 실행 시 내부적으로 영어로 번역합니다.
예: soft wind through tall grass, distant birds, light footsteps
한국어 예: 잔잔한 바람, 멀리서 들리는 새소리, 가벼운 발걸음

music_mode (배경 음악)
등장인물에게는 들리지 않고 시청자에게만 들리는 배경 음악을 선택합니다.
예: 잔잔한 감성 장면 → `절제된 피아노 + 저음 현악`

music_hint (배경 음악 직접 입력)
R2V에서도 `▶ 사운드` 그룹을 펼치면 기본 보기에서 환경음과 배경 음악의 대표 모드를 빠르게 선택합니다. 직접 입력 모드를 선택한 경우에는 필요한 `환경음 직접 입력` 또는 `배경 음악 직접 입력` 칸이 기본 보기에서도 즉시 나타납니다. 전체 설정 보기에서는 이 직접 입력칸을 선택 모드와 무관하게 확인할 수 있습니다. 새 노드와 설정 초기화 직후에는 사운드 그룹 자체가 접혀 있으므로 헤더를 먼저 펼치십시오.
관객에게만 들리는 `시청자용 배경 음악(non_diegetic_music)`을 보강합니다. MiniMax H3 공식 규칙에 맞춰 악기 구성, 템포/속도, 리듬, 질감, 강약 변화와 페이드 같은 실제 음악적 속성을 중심으로 적습니다. `슬픈`, `로맨틱한`, `영웅적인`, `관객에게 감동을 주는`처럼 추상적인 분위기·감정 기능만 설명하는 방식은 피하는 것이 좋으며, 이런 문구가 감지되면 info에 경고합니다. 라디오/TV/휴대폰 등 장면 속 인물도 듣는 음악은 non-diegetic이 아니므로 장면 설명/행동 쪽에 적어야 합니다. 한국어는 내부적으로 영어로 번역합니다. 프리셋 음악을 선택했다면 해당 프리셋의 악기/구조에 추가 설명을 합치고, `직접 입력한 음악`에서는 직접 입력을 음악 지시로 사용합니다. `사용 안 함`이면 무시됩니다. 프리셋에는 클래식 기타, 잔잔한 경음악·클래식, 서정적 하프 + 첼로, 라이트 재즈, 보사노바, 한국 전통 퓨전, 고전·빈티지 팝, 모던 팝, K-pop 스타일·댄스, 빠른 랩 비트, 올드스쿨 힙합, 펑키 그루브, 록, 앰비언트·전자 음악, 신스웨이브·드림 팝, 시네마틱 퍼커션·오케스트라, 경쾌한/장엄한 행진곡, 천공·우주 음악, 판타지 등도 포함됩니다. `빠른 랩 비트`와 K-pop 계열은 실제 랩/노래 가사를 만드는 메뉴가 아니라 시청자용 반주 스타일이며, 실제 보컬/가사는 시간순 진행에서 지정합니다.
예: sparse piano at 70 BPM with sustained low strings, gradually fading out
한국어 예: 절제된 피아노, 느린 템포, 낮게 지속되는 현악기, 끝부분에서 점차 페이드아웃

person_count (주요 인물 수)
시간순 진행에서 구분해서 다룰 주요 인물의 수를 선택합니다.
예: 여성과 남성 두 명을 각각 제어하려면 `2`
내부 프롬프트에서는 여러 인물을 안정적으로 추적하기 위해 `Person A`, `Person B`, `Person C` 같은 식별자를 사용합니다. 성별·연령·외형·복장 같은 전체 프로필은 처음 필요한 위치에서 한 번 확실히 소개하고, 이후 시간순 진행에서는 가능한 한 `Person A/B/C` 중심으로 짧게 이어서 같은 프로필을 반복하지 않습니다. 음성 특징은 해당 인물의 첫 실제 발화에서만 붙습니다.

장면 설명에서 `Person A/B/C`를 직접 구조 인물명으로 쓸 때도 현재 인원 수 범위를 확인합니다. 예를 들어 인원 수가 1명인데 `Person B` 또는 `Person C`를 명시하면 익명 추가 인물로 흘려보내지 않고 친절하게 실행을 차단합니다. 일반적인 `a passerby`, `people in the background` 같은 표현과 큰따옴표 안의 화면 문자 `"Person B"`는 이 구조 검사 대상이 아닙니다.

영어 시간순 진행 행동이 일반적인 인물 표현으로 시작해도 진행 대상에서 선택한 `Person A/B/C`가 같은 인물의 권위 있는 식별자로 유지됩니다. `A woman walks ...`처럼 수식어가 없는 기본 문장은 프로필과 행동을 불필요하게 두 문장으로 나누지 않고 기존의 간결한 한 문장 형태를 유지합니다. `A young woman ...`, `A tall, nervous man ...`, `An elderly woman ...`처럼 인물명사 앞에 수식어가 있어도 별도 인물로 분리되지 않으며, 노드에서 성별·연령을 지정했다면 그 설정을 우선하고 `tall`, `nervous`, `East Asian`처럼 프로필과 충돌하지 않는 묘사는 같은 Person에 보존합니다. `A woman covered in mud ...`, `A man armed with ...`, `A woman seated by ...`, `A man wrapped in ...`, `The person holding ...` 같은 후치수식 표현도 같은 Person 행동으로 결속합니다. 합동 진행에서도 `A woman and a man ...`, `two people ...` 같은 자연어 인물 그룹을 선택된 Person 조합에 연결합니다. 반대로 `A portrait of a woman ...`, `A camera ...`, `A dog ...`처럼 실제 인물이 주어가 아닌 장면·사물 문장은 독립 주어로 유지됩니다.

person_a/b/c_gender · age · advanced · appearance_preset · appearance_desc · clothing_preset · clothing_desc · voice_desc (인물 프로필)
각 인물은 빠른 기본 항목과 고급 세부 항목으로 나뉩니다. 기본 보기에서는 활성된 모든 인물의 성별·연령대·민족적 외형을 바로 확인하고 수정할 수 있습니다. 전체 설정 보기에서는 `○/● 인물 N 고급 설정`을 한 번 클릭하면 음성 특징, 외형 프리셋, 외형 추가 입력, 의상 프리셋, 의상 추가 입력이 즉시 펼쳐지거나 접힙니다. 왼쪽 `○`는 접힘, `●`는 펼침 상태를 뜻하며 우측 `▶/▼` 토글과 동기화됩니다. 숨겨진 값은 삭제되지 않으며 다시 열거나 인원 수를 되돌리면 복원됩니다. 외형·의상·목소리 특징은 영어 입력을 권장하며 한국어라면 내부 번역 후 H3 인물 설명에 사용합니다.
예: 인물 1 = 여성 / 30대 / `●` 고급 설정 펼침 / `슬림한 체형` + `긴 검은 머리` / `코트와 스커트` + `베이지색 트렌치코트` / `밝고 부드러운 목소리`

turn_count (시간순 진행 수)
화면에 사용할 시간순 진행 칸 수를 1~6 사이에서 선택합니다. 각 진행 칸은 같은 시점의 행동·대사 한 묶음을 의미합니다. 다른 인물의 다른 행동·대사·시점을 넣고 싶다면 다음 진행 칸을 사용합니다. 현재 실행 경로는 시간순 진행 전용이며 `turn_count`의 유효 범위는 1~6입니다.
예: 서로 다른 세 장면 단계가 필요하면 `3`

turn_n_speaker (진행 N 대상 인물)
해당 진행의 대상 인물을 선택합니다. 한 진행은 같은 시점의 행동·대사 한 묶음이므로 다른 인물의 다른 사건은 다음 진행 칸에 작성합니다.
예: 진행 1 = 인물 1, 진행 2 = 인물 2

turn_n_elapsed_seconds (진행 N 시작 시점)
이 진행이 영상 시작 후 어느 시점 부근에서 시작되기를 원하는지 입력합니다. 0.5초 단위이며 직접 더 세밀한 소수값을 입력해도 가장 가까운 0.5초로 즉시 정규화됩니다. 예를 들어 `0.50123`은 `0.5`, `0.75123`은 `1.0`으로 처리됩니다. 최대값은 `영상 길이 - 0.5초`로 자동 제한됩니다. 예를 들어 10초 영상이면 0.0~9.5초, 5초 영상이면 0.0~4.5초입니다. 영상 길이를 줄여 기존 시작값이 새 범위를 넘으면 UI 값도 새 최대값으로 눈에 보이게 조정됩니다. 실제 위젯 값, 접힌 진행 요약, Queue 전달값과 최종 프롬프트 시간은 같은 0.5초 정규화값을 사용합니다. 프레임 단위의 엄격한 타임코드가 아니라 대략적인 기준점이며, 자연스러운 순차 진행과 정상적인 동작 속도를 우선합니다.
예: 10초 영상에서 진행 2의 대사가 약 5초 부근에서 시작 → `5.0`

turn_n_action (진행 N 행동)
그 시점에 화면에서 실제로 일어나는 행동을 적습니다. 가급적 영어를 권장하지만 한국어 입력도 가능하며, 실행할 때 내부적으로 영어로 번역한 뒤 반드시 행동 필드로만 사용합니다. 대사로 승격하지 않습니다.
예: 여성이 천천히 남성을 바라보고 미소 짓는다.

같은 진행에 실제 대사도 입력했다면 행동칸에는 화면에 보이는 동작을 중심으로 적고, `말한다`, `대화한다`, `speaks`, `talks`처럼 **내용이 지정되지 않은 별도 발화 지시를 대사와 중복해서 쓰지 않는 것**을 권장합니다. 실제 발화 내용은 `진행 N 대사` 또는 이어 말하기의 `발화 N → 대사`가 권위 입력입니다. 노드는 명시적 대사가 있는 경우 행동 끝에 붙은 단순한 내용 미지정 `speaks/talks/says`류 중복 발화 표현만 좁게 생략하여 불필요한 추가 음성 힌트를 줄입니다. `speaks softly`, `talks to Person B`, `whispers`, `shouts`, `sings`처럼 전달 방식이나 대상/의미가 포함된 표현은 임의로 삭제하지 않습니다. 이 방어는 H3가 임의 음성을 절대 생성하지 않는다는 보장은 아니며, 모델 자체의 오디오 변동성은 별개입니다.

turn_n_dialogue_text (진행 N 대사)
실제로 말할 문장을 원문 그대로 적습니다. 자동번역하지 않습니다.
예: 오늘 날씨 정말 좋다.

turn_n_dialogue_language (진행 N 대사 언어)
대사에 붙일 H3 언어 태그를 선택합니다. 한국어/영어는 보통 자동으로 충분합니다.
예: 한국어 대사 → `자동` 또는 `Korean`

turn_n_dialogue_delivery (진행 N 말하는 방식)
화면 속 인물이 직접 말할지, 화면 밖 보이스오버로 말할지 선택합니다.
예: 화면에 보이는 여성이 직접 말함 → `화면 속 직접 대사`

start_image / end_image (시작 이미지 / 마지막 이미지)
H3 모드 판별용 이미지 연결입니다. 이 노드는 픽셀을 분석하지 않습니다.
예: I2VA에서는 Load Image의 원본 이미지를 `시작 이미지`와 MiniMax H3 `first_frame`에 함께 분기 연결

h3_prompt 출력
최종 MiniMax H3 프롬프트입니다. 실제 H3 영상 생성 노드의 prompt/text 입력 흐름에 연결합니다.

info 출력
판별된 모드, 활성 인물/진행 수, 번역 상태, 경고를 확인하는 진단용 문자열입니다.


============================================================
5. 전체 장면 / 배경
============================================================

`전체 장면 / 배경`은 영상 전체에 공통으로 유지될 내용을 적는 곳입니다.

권장 내용:

- 장소
- 배경
- 분위기
- 시간대
- 조명
- 영상 시작 시점의 인물 배치
- 화면 전체에 공통인 상태

예:

조용한 카페의 창가 자리. 젊은 여성과 남성이 작은 테이블을 사이에 두고 마주 앉아 있다. 늦은 오후의 부드러운 햇빛이 창문으로 들어온다.

시간이 지나면서 바뀌는 행동과 실제 대사는 이곳에 반복해서 넣기보다 아래 `시간순 진행`에 적는 것이 좋습니다.

예를 들어 다음 내용은 시간순 진행에 더 적합합니다.

- 2초에 여성이 자리에서 일어난다.
- 4초에 남성이 창밖을 바라본다.
- 5초에 여성이 "가자"라고 말한다.


============================================================
6. 장면 설명 번역 — 기본값은 자동
============================================================

`장면 설명 번역`의 기본값은 자동입니다.

자동 설정의 동작:

- 전체 장면 / 배경이 한국어라면 → 영어로 자동번역. 이 안의 `인물 1/2/3`도 번역 전에 `Person A/B/C` 구조로 보호하며, 외부 번역기에는 번역 전용 고유 식별자로 전달한 뒤 최종 프롬프트에서 다시 `Person A/B/C`로 복원합니다. 일반 단어와 대명사는 강제 치환하지 않습니다.
- 이미 영어이면 → 번역 요청 없이 그대로 사용
- 대사 → 번역하지 않음, 원문 그대로 유지
- 시간순 진행의 행동 → 한국어라면 행동 전용 경로에서 영어로 내부 번역
- 환경음 직접 입력 / 배경음악 직접 입력 / 외형 / 복장 / 음성 특징 → 한국어라면 각각 영어로 내부 번역
- 배경음악 직접 입력은 프리셋을 선택해도 무시되지 않고 선택한 프리셋을 보강합니다. 단, 배경 음악이 `사용 안 함`이면 배경음악 직접 입력도 사용하지 않습니다.

따라서 일반적인 한국어 사용자는 별도의 조작 없이 전체 장면 / 배경과 진행 행동을 한국어로 작성할 수 있습니다. 다만 H3에 직접 들어가는 설명문은 영어가 가장 명확하므로 툴팁에서는 영어 입력을 우선 권장합니다.

예:

입력:
조용한 골목길에서 두 사람이 천천히 걷는다.

자동 설정:
한국어 장면 부분을 영어 H3 본문으로 변환

영어 입력:
Two people walk slowly through a quiet alley.

자동 설정:
이미 영어이므로 그대로 사용

`사용 안 함 · 입력 그대로`를 선택하면 장면 설명뿐 아니라 진행 행동, 인물 외형·의상·음성 설명, R2V Reference의 설명·적용 지시어, 환경음, 음악 등 모든 비대사 서술 항목의 온라인 번역을 건너뜁니다.
각 입력은 그대로 H3 프롬프트 조립 단계로 전달되며, 대사는 원래부터 번역하지 않습니다. 한국어 비대사 서술을 그대로 H3 본문에 넣고 싶은 경우에 사용하십시오.

자동번역은 인터넷 연결이 필요합니다.
API 키는 필요하지 않습니다.

번역은 요청별 Google JSON 경로를 먼저 사용하고, 정상적인 Google 오류에서는 Google mobile 호환 경로를 보조로 사용합니다.
Google에서 HTTP 429가 발생하면 같은 Google 경로를 연속 호출하지 않고 provider별 cooldown으로 전환한 뒤 독립 서비스인 MyMemory를 자동 fallback으로 사용합니다. 요청이 연속으로 많아질 때는 간격을 점진적으로 늘리고, 반복 429에는 지수형 cooldown을 적용하며 서버의 Retry-After도 가능한 범위에서 우선합니다. cooldown 상태는 ComfyUI 재시작 후에도 유지됩니다.
Google 계열에서 성공한 동일 번역은 ComfyUI 사용자 영역에 최대 2048개·30일 범위로 보존되어 재시작 후에도 재사용됩니다. 캐시 키는 NFC/개행/앞뒤·줄끝 공백 정도만 보수적으로 정규화하며 마침표·쉼표·단어가 달라지면 별도 문장으로 취급합니다. MyMemory 결과는 Google 복구 뒤에도 다른 번역이 영구 고정되는 것을 피하기 위해 디스크 캐시에 저장하지 않습니다. deep-translator는 이미 설치된 경우에만 마지막 호환 fallback으로 사용할 수 있으며 필수 설치 항목은 아닙니다.
모든 온라인 경로가 실패하면 임의의 영어 문장으로 바꾸지 않고 번역 실패를 명확히 알려줍니다.

중요:
큰따옴표 안의 화면 글자는 가능한 한 원문 그대로 보존합니다.

예:

"영업중"
"OPEN"
"A  B"

간판, 자막, 네온, 라벨처럼 화면에 실제로 보일 문자열은 번역 과정에서 별도로 보호합니다.

[자동번역이 임의로 I / We / You를 만드는 경우]

한국어 장면 문장은 주어를 생략하는 경우가 많습니다.
예를 들어:

넓은 풀밭을 걸어가고 있다.

처럼 사용자가 `나`, `우리`, `너`를 쓰지 않았는데 번역기가 임의로
`I am walking ...`, `We are walking ...`, `You are walking ...`처럼 인칭을 만들면,
노드는 원문에 없던 1·2인칭 관점만 중립적인 영어 표현으로 정리합니다.

반대로 원문에 실제 인칭이 있으면 그 의도를 없애지 않습니다.

- 나는 / 내가 / 저는 / 제가 → 명시된 1인칭 단수로 취급
- 우리 / 우리들 / 저희 / 저희들 → 명시된 1인칭 복수로 취급
- 너 / 너희 / 너희들 / 당신 / 당신들 / 그대 / 여러분 → 명시된 2인칭으로 취급
- 그녀가 / 그 남성이 / 그들이처럼 명시된 3인칭 → 정상적인 She / He / They 번역을 그대로 유지

`함께`, `둘이`, `서로`처럼 복수 인물이 있다는 뜻만 있고 `우리/저희`가 없는 문장은
번역기가 임의로 `We`를 넣었다고 해서 사용자가 1인칭 시점을 지정한 것으로 보지 않습니다.
큰따옴표 안의 화면 글자는 이 인칭 보정에서도 보호합니다.

[대사를 제외한 한국어 자유입력 처리]

H3 본문에 설명문으로 들어가는 자유입력은 가능한 한 영어로 정리합니다.
현재 한국어 내부 번역 대상은 다음과 같습니다.

- 전체 장면 / 배경: `장면 설명 번역`이 자동일 때 번역
- 진행 N 행동: 한국어라면 자동 번역 후 행동으로만 사용
- 환경음 직접 입력: 실제 사용되는 한국어 입력은 영어로 번역
- 배경음악 직접 입력: 한국어라면 영어로 내부 번역합니다. 프리셋 음악을 선택했다면 그 프리셋에 분위기·질감 등의 추가 지시로 합쳐지고, `직접 입력한 음악` 모드에서는 직접 입력 내용만 음악 지시로 사용합니다. `사용 안 함`에서는 무시됩니다.
- 인물 N 외형·복장: 한국어라면 영어로 번역 후 해당 인물의 첫 실제 등장 설명에 사용
- 인물 N 음성 특징: 한국어라면 영어로 번역 후 첫 발화의 음성 설명에 사용

반대로 `진행 N 대사`와 구형 단일 대사 입력은 실제 발화 원문이므로 자동번역하지 않습니다.


============================================================
7. 영상 길이 (초)
============================================================

MiniMax H3의 영상 길이와 맞춰 사용하는 시간 검증 기준입니다.

허용 범위:

- 4초 ~ 30초
- 정수만 허용

예:

5 → 정상
10 → 정상
15 → 정상
7.5 → 허용하지 않음

이 값은 실제 영상 생성 노드의 duration을 직접 변경하는 기능이 아닙니다.
실제 MiniMax H3 영상 생성 노드에서 사용하는 영상 길이와 같은 값으로 맞추십시오.

이 값은 다음을 검사하는 데 사용됩니다.

- 진행 시작 시점이 영상 길이를 넘는지
- 모든 진행이 시작 시점 기준으로 올바르게 정렬되는지
- 대사가 현재 구간에 비해 지나치게 긴지 (복수 촬영에서는 다음 컷까지, 마지막 촬영에서는 영상 끝까지)
- H3 시간 표현이 올바른 범위인지


============================================================
8. 영상 입력 방식
============================================================

`자동` 사용을 권장합니다.

자동 판별:

- 이미지 연결 없음 → T2VA
- 시작 이미지만 연결 → I2VA
- 마지막 이미지만 연결 → L2VA
- 시작 이미지 + 마지막 이미지 → FL2VA

수동 모드는 연결 상태보다 사용자가 고른 모드를 우선합니다. T2VA를 직접 선택하면 시작/마지막 이미지가 연결되어 있어도 프롬프트 모드 판정에서는 그 이미지를 무시하고 T2VA로 동작합니다. I2VA는 시작 이미지, L2VA는 마지막 이미지, FL2VA는 시작+마지막 이미지가 필수입니다. 필요한 이미지가 빠진 경우 다른 모드로 자동 보정하지 않으며, 최상단 지시어 영역에 해당 이미지 연결 안내를 먼저 한 개만 표시하고 Queue 자체를 native 오류로 만들지 않은 채 `h3_prompt` 실행만 `waiting_for_reference` 상태로 대기시킵니다. 이미지 연결 문제가 해결된 다음 Queue에서 다른 독립적인 입력 문제가 있다면 그 안내가 순차적으로 표시됩니다.

중요:
이 노드는 이미지 픽셀을 분석하지 않습니다.
이미지 연결 여부는 H3 입력 방식과 참조 문구를 정하기 위한 신호로만 사용합니다.

권장 연결 방식은 원본 Load Image를 먼저 분기하는 것입니다.

I2VA에서 장면과 진행 행동을 모두 비워도 존재하지 않는 `requested action`을 언급하지 않고 참조 프레임 유지 문구만 생성합니다. 이미지 기반 보이스오버도 참조 이미지에 사람이 있다고 가정하지 않으며, 존재하지 않을 수 있는 화면 인물의 입술을 강제로 언급하지 않습니다. `visual_style=auto`인 이미지 모드에서는 info에 `reference_preserved`가 표시됩니다.

I2VA 예:

Load Image 원본 IMAGE
  ├─→ Ultra MiniMax H3 Prompt : 시작 이미지
  └─→ Image to Video (MiniMax H3) : first_frame

영상 width / height는 별도의 해상도 선택기 또는 크기 계산 흐름에서 연결합니다.
예를 들어 ImageScaleToTotalPixels를 해상도 계산에 사용하더라도, 축소된 이미지를 굳이 first_frame에 넣기보다 원본 IMAGE를 first_frame에 직접 연결하고
그 리사이즈 결과의 width / height만 영상 생성 노드에 사용하는 구성을 권장합니다.

FL2VA라면 마지막 이미지도 같은 방식으로 분기합니다.

Last Image 원본 IMAGE
  ├─→ Ultra MiniMax H3 Prompt : 마지막 이미지
  └─→ Image to Video (MiniMax H3) : last_frame

이렇게 하면 Prompt 노드의 모드 판별과 실제 H3의 first/last frame이 같은 원본을 기준으로 동작합니다.


============================================================
9. 주요 인물 수
============================================================

시간순 진행에서 구분해서 사용할 주요 인물의 수입니다.

- 1명
- 2명
- 3명

UI에서는 다음처럼 표시합니다.

- 인물 1
- 인물 2
- 인물 3

여기서 인물 1/2/3은 영상 속 캐릭터를 구분하기 위한 번호입니다.
H3의 S1/S2/S3와 고정 연결되는 번호가 아닙니다.


============================================================
10. S1 / S2 / S3는 어떻게 정해지나요?
============================================================

H3 화자 ID는 실제 대사가 처음 등장한 순서대로 자동 배정됩니다.

예:

인물 1 = 여성
인물 2 = 남성

0초: 두 사람이 함께 걷는다. 대사 없음
2초: 인물 2가 "오늘 날씨 좋네."라고 말한다.
5초: 인물 1이 "그러게."라고 말한다.

결과:

- 인물 2 → S1
- 인물 1 → S2

인물 1이 화면에 먼저 있었더라도, 먼저 말한 인물 2가 S1입니다.

행동만 하는 진행은 S 번호를 소비하지 않습니다.

예:

0초: 인물 1이 문을 연다. 대사 없음
2초: 인물 2가 말한다.
4초: 인물 1이 말한다.

결과:

- 인물 2 → S1
- 인물 1 → S2

한 번 S ID가 배정된 인물은 영상 끝까지 같은 ID를 유지합니다.


============================================================
11. 여러 인물이 동시에 말할 때
============================================================

대상 인물에서 복합 선택을 사용할 수 있습니다.

주요 인물 2명:

- 인물 1
- 인물 2
- 인물 1 + 2

주요 인물 3명:

- 인물 1
- 인물 2
- 인물 3
- 인물 1 + 2
- 인물 1 + 3
- 인물 2 + 3
- 인물 1 + 2 + 3

복합 선택에서 대사를 입력하면 해당 인물들이 함께 말하는 H3 복합 화자 형식으로 구성됩니다.

예:

1초: 인물 2가 먼저 말함 → 인물 2 = S1
3초: 인물 1 + 2가 함께 말함 → 인물 1이 처음 말하므로 S2 배정

공동 발화는 내부적으로 S ID 순서에 맞춰 (S1,S2) 형식으로 정리됩니다.
같은 복합 진행에 행동과 대사가 함께 있으면 행동 문장과 대사 문장의 인물 나열도 같은 S ID 순서로 통일합니다. 따라서 앞 문장에서는 `인물 1 + 2`, 바로 다음 문장에서는 `인물 2 + 1`처럼 순서가 뒤집혀 보이지 않습니다. 행동만 있는 복합 진행은 기존처럼 인물 1/2/3 선택 순서를 사용합니다.

처음 대사부터 두 명이 완전히 동시에 말하면 시간상 우선순위가 없으므로,
그 복합 선택 안의 인물 번호 순서를 안정적인 동률 처리 기준으로 사용합니다.

실제로 동시에 말하는 장면을 만들고 싶으면 같은 시각의 단독 진행 두 개를 만드는 것보다 `인물 1 + 2` 같은 복합 선택을 사용하는 것이 명확합니다.


============================================================
12. 인물 프로필
============================================================

각 인물에는 기본 항목과 고급 항목이 있습니다.

기본 항목:

- 성별
- 연령대
- 고급 설정 직접 토글

고급 항목:

- 민족적 외형
- 음성 특징
- 외형 프리셋
- 외형 추가 입력
- 의상 프리셋
- 의상 추가 입력

`고급 설정`은 선택 목록이 아니라 직접 토글입니다. 접힌 상태의 왼쪽 `○` / 우측 `▶` 조합을 클릭하면 즉시 왼쪽 `●` / 우측 `▼`로 바뀌며 세부 프로필이 펼쳐지고, 다시 클릭하면 `▶`로 접힙니다. 이 값들은 고급 항목을 숨기거나 인원 수를 줄여도 지워지지 않으며 다시 표시하면 이전 입력이 그대로 복구됩니다.

중요: `고급 설정`을 접거나 `주요 인물 수`·`시간순 진행 수`를 줄이거나 촬영 컷을 비활성화하는 일반적인 화면 변경은 사용자가 만든 설정을 버리는 동작이 아닙니다. 직접 입력한 값은 그대로 보존되며, 잠시 활성 구조에서 빠지는 인물/진행/Shot의 외부 STRING 연결은 숨겨진 단자에 유령선을 남기지 않도록 일시 해제한 뒤 원래 상류 출력 위치를 기억합니다. 같은 수를 다시 늘리면 해당 행과 함께 원래 연결을 복원합니다. 이 기억을 완전히 지우는 동작은 확인 후 실행되는 `설정 초기화`뿐입니다.

제목줄 툴팁 ON/OFF: Main과 R2V 노드 제목 오른쪽에는 작은 `툴팁 ON / 툴팁 OFF` 토글이 있습니다. 노드별로 툴팁 표시를 잠시 끄거나 다시 켤 때 사용하며, 화면 표시 전용이라 프롬프트 값·입력 순서·노드 크기·Reference 구조에는 영향을 주지 않습니다. 상태는 워크플로우에 노드별로 저장됩니다. OFF에서는 Ultra 툴팁만 표시하지 않으며 기존 native 구형 툴팁이 다시 나타나지는 않습니다.

외부 STRING 내용 툴팁: Main의 T2V/I2V와 R2V에서 STRING으로 연결할 수 있는 항목은 외부 STRING이 실제 연결되어 있을 때 기존 도움말 대신 연결된 문자열 내용을 툴팁으로 표시합니다. 연결하지 않은 항목은 기존 도움말이 그대로 표시됩니다. 빈 문자열은 `(빈 문자열)`로 표시하고, 너무 긴 문자열은 약 420자 선에서 `… (이하 생략)`으로 화면 표시만 줄입니다. 실제 입력값·생성 프롬프트는 자르거나 바꾸지 않습니다. 직접 Text 계열처럼 프론트엔드에서 현재 값을 확실히 읽을 수 있는 연결은 그 값을 표시하며, 실행해야만 결과가 결정되는 중간 처리 노드는 값을 추측하지 않고 `외부 STRING 연결 · 현재 값은 실행 시 결정됩니다.`라고 표시합니다. 이 기능은 마우스 툴팁 표시용이며 주기적 polling, Reference rebuild, 노드 크기 변경, 연결 재배치, 저장값 변경을 수행하지 않습니다. Ultra Textbox에서 직접 연결한 경우에만 해당 출력 행의 실제 번호를 함께 표시하여 `Text 9 : 연결된 문장`처럼 원본 Text 칸을 바로 찾을 수 있습니다. 일반 독립 STRING 노드나 다른 멀티 텍스트 노드에는 임의의 `STRING`/번호 접두어를 붙이지 않고 기존처럼 문장만 표시합니다. 외부 STRING이 연결된 항목의 라벨 앞에는 작고 단순한 `↖` 표시가 붙어 연결 상태를 한눈에 구분할 수 있으며, 연결을 해제하면 자동으로 사라집니다. 이 표시는 라벨 표시만 바꾸며 위젯 값·위치·노드 크기·연결 구조에는 영향을 주지 않습니다. 또한 Main과 R2V의 최상단 지시어 placeholder는 현재 메뉴 언어에 맞춰 같은 문구로 통일됩니다. 한글은 `영상의 장면과 원하는 연출을 입력하세요`, 영문은 `Describe the video scene and desired direction`을 사용합니다. 완전히 빈 Main T2VA 초안은 ComfyUI native validation 오류로 만들지 않지만, Queue 시 최상단 지시어 영역의 Ultra 안내 배지에 필요한 장면/환경/행동·대사 입력을 알려 주고 `h3_prompt`만 `waiting_for_content` 상태로 조용히 대기합니다. 수동 I2VA/L2VA/FL2VA에서 필수 이미지가 빠진 경우에도 같은 배지 위치를 사용하며, 이미지 연결 안내를 가장 먼저 한 개만 표시합니다. 이 안내가 해결된 다음 Queue에서 다른 독립적인 입력 문제가 있다면 그 다음 안내가 순차적으로 표시됩니다.

[현재 UI의 기준 상태 · 반드시 이 설명을 기준으로 사용]
- 새 Main/R2V 노드와 `설정 초기화` 직후에는 **기본 보기 + 모든 그룹 접힘** 상태입니다. 최상단 `전체 장면 / 배경` 입력창만 그룹 밖에서 항상 보이고, 아래에는 `▶ 기본 설정`, `▶ 촬영 설정`, `▶ 사운드`, `▶ 인물 1`, `▶ 진행 1`처럼 접힌 헤더가 표시됩니다. R2V Reference를 실제 연결하면 해당 `이미지/영상/오디오 참조 N` 그룹이 `전체 장면 / 배경` 바로 아래에 추가되며 `▶/▼`로 독립적으로 접고 펼칠 수 있습니다.
- 그룹 내용을 보려면 해당 `▶` 헤더를 클릭해 `▼`로 펼치십시오. 하단 `전체 설정 보기 / 기본 보기`는 그룹을 펼치거나 접는 버튼이 아닙니다. 기본 보기는 빠른 편집용 핵심 행만 남겨 화면을 눈에 띄게 줄이고, 전체 설정 보기는 숨겨 둔 정밀 제어를 다시 표시합니다. 보기 모드를 왕복해도 각 그룹의 접힘/펼침 상태는 독립적으로 유지됩니다.
- 새 노드의 `전체 장면 / 배경` 입력창은 Core native multiline 위젯 기준 약 5줄 높이로 시작합니다. 사용자가 높이를 조절한 뒤 인원/진행/촬영/Reference 구조가 바뀌어도 그 작업 높이를 유지하고, 새로 보이거나 사라지는 고정 행만큼 노드 바닥이 늘거나 줄어듭니다.
- `설정 초기화`도 현재 `전체 장면 / 배경` 작업 높이를 유지합니다. 설정값을 기본값으로 돌리고 모든 그룹을 접으며, 초기화로 사라지는 고정 행만큼 노드 외곽 높이가 줄어듭니다. 시작/마지막 이미지(Main)와 Picture/Video/Audio Reference(R2V)의 실제 미디어 연결은 유지됩니다.
- 동적 구조를 결정하는 핵심 선택기는 외부 값 연결을 지원하지 않습니다. Main은 `영상 입력 방식`, `영상 길이 (초)`, `주요 인물 수`, `시간순 진행 수`, `여러 촬영 컷 사용`, `촬영 컷 2~6 시작`; R2V는 `영상 길이 (초)`, `주요 인물 수`, `시간순 진행 수`, `여러 촬영 컷 사용`, `촬영 컷 2~6 시작`을 노드 안에서 직접 설정해야 합니다. 이는 화면에 보이는 인물/진행/촬영 구조와 Queue에서 Python이 실제 사용하는 값이 달라지는 상황을 막기 위한 의도적인 제한입니다. 장면/행동/대사/인물 자유입력/사운드·음악 등 일반 콘텐츠 입력과 실제 미디어 Reference 연결은 기존 방식대로 사용할 수 있습니다. 오래된 수동 워크플로에 구조 선택기의 외부 연결이 이미 남아 있다면 자동으로 끊지 않으므로 사용자가 직접 해제한 뒤 다시 저장하십시오.
- Subgraph/promoted widget은 ComfyUI frontend의 직렬화·승격 계층에 속하므로 이 노드가 추측성 보정을 추가하지 않습니다. Subgraph에서 값을 promote해 사용할 경우 실사용 환경에서 저장 → 다른 워크플로 전환 → 재로드 → Queue 후 화면값과 생성 프롬프트가 일치하는지 확인하십시오.

노드 맨 아래에는 `기본 보기` / `전체 설정 보기` 토글이 있습니다. 이 토글은 프롬프트 실행값을 바꾸지 않고 **이미 펼쳐진 그룹 안에서** 빠른 핵심 행과 정밀 행의 표시 범위만 조절합니다. 기본 보기에서도 현재 활성화된 인물/진행 그룹 자체는 사라지지 않으며, 각 인물의 성별·연령대·민족적 외형과 각 진행의 대상·시작 시점·행동·대사는 계속 사용할 수 있습니다. 각 그룹 헤더의 `▶/▼` 접힘 상태와는 별개이므로 `전체 설정 보기`를 눌러도 접힌 그룹이 자동으로 열리지는 않습니다. 인물 고급 세부 행은 보기 모드에 따라 숨거나 다시 나타날 수 있지만 저장된 프로필 값은 유지됩니다. 기본 보기에서 인원 수나 시간순 진행 수를 바꿔도 보기 모드는 그대로 유지되고 새로 활성화된 인물/진행 그룹의 핵심 행만 추가됩니다. 여러 촬영 컷의 구조(활성 컷 ON/OFF, 시작시점, 대상, 구도)는 기본 보기에서도 순차적으로 편집할 수 있습니다. 촬영 컷 1의 기본 카메라 이동 폭·속도, 촬영 컷 2~6의 전환 방식·개별 카메라 움직임·개별 이동 폭·속도, 진행별 환경/대사 세부 같은 정밀 조정은 `전체 설정 보기`에서 편집합니다. 보기 상태와 그룹 접힘 상태는 UI 상태일 뿐 프롬프트 값에는 영향을 주지 않습니다. 기본 보기에서 원래 숨길 세부 항목이라도 외부 STRING/위젯 입력이 실제 연결된 행은 연결 단자와 선을 화면에서 숨기지 않기 위해 그대로 표시될 수 있습니다. 이것은 값 변경이 아니라 유령선/유령단자 방지를 위한 연결 가시성 예외입니다.

Main `Ultra MiniMax H3 Prompt`를 새로 추가하거나 `설정 초기화`한 직후에는 모든 그룹이 접혀 있으므로 `촬영 컷 1 대상`이나 `○ 인물 1 고급 설정`이 바로 보이지 않는 것이 정상입니다. 먼저 `▶ 촬영 설정` 또는 `▶ 인물 1` 헤더를 클릭해 `▼`로 펼치십시오. 인물 그룹 안에서 `○ 인물 1 고급 설정`을 사용하려면 필요에 따라 `전체 설정 보기`로 전환한 뒤 고급 설정을 펼칩니다. `촬영 컷 1 구도`는 촬영 대상을 인물/인물 조합으로 선택했을 때 인물용 선택지가 열리고, 비인물 대상에서는 `자동 · 장면에 맞춤`만 사용할 수 있습니다.

`설정 초기화`는 `기본 보기 / 전체 설정 보기`와 함께 노드 맨 아래의 ComfyUI 기본 버튼 위젯으로 표시됩니다. 두 번 클릭 확인 방식이며 resettable widget 값과 숨은 복원 상태를 새 노드 기본값으로 돌리고 **기본 보기 + 모든 그룹 접힘** 상태로 정리합니다. Main의 시작/마지막 이미지와 R2V의 Picture/Video/Audio Reference 같은 고정 미디어 연결은 유지하지만, 초기화 대상 일반 설정 위젯의 외부 연결과 기억은 정리됩니다. 중요한 차이는 `전체 장면 / 배경` 작업 높이를 새 노드 크기로 강제로 되돌리지 않는다는 점입니다. 사용자가 확보한 씬 입력 높이는 그대로 유지하고, 초기화로 사라지는 고정 행 높이만큼 노드 바닥만 Core 레이아웃에 따라 위로 올라옵니다.

성별:

- 지정 안 함
- 여성
- 남성
- 남성·여성 이외 (논바이너리)

연령대:

- 지정 안 함
- 어린이
- 청소년
- 20대
- 30대
- 40대
- 50대
- 60대
- 노년

화면에는 연령대가 간단하게 표시되지만 최종 H3 프롬프트에는 자연스러운 영어 문장으로 들어갑니다.
예:

- 여성 / 20대 → `a young woman in her twenties`
- 여성 / 30대 → `a woman in her thirties`
- 남성 / 50대 → `a man in his fifties`
- 남성 / 60대 → `a man in his sixties`
- 여성 / 노년 → `an elderly woman`

즉 `30s` 같은 짧은 토큰을 그대로 넣는 방식이 아니라 인물 설명에 자연스럽게 결합합니다.

`민족적 외형`은 각 `인물 N`의 기본 정체성 항목으로 분류되어 기본 보기에서도 성별·연령대와 함께 바로 표시됩니다. `지정 안 함`, `한국인 외형`, `동아시아계 외형`, `동남아시아계 외형`, `남아시아계 외형`, `중앙아시아계 외형`, `중동·서아시아계 외형`, `유럽계 외형`, `아프리카계 외형`, `라틴아메리카계 외형`, `혼합 계통 외형`을 선택할 수 있습니다. 이 값은 외형 프리셋이나 외형 추가 입력을 대체하지 않고 함께 조합됩니다. 예를 들어 `한국인 외형 + 탄탄한 체형 + 긴 검은 머리`는 최종 인물 설명에서 `Korean facial features, an athletic build, long black hair`처럼 자연스럽게 합쳐집니다. I2V/R2V에서는 시작 이미지나 Reference의 실제 인물 외형이 더 강한 정체성 기준으로 작용할 수 있으므로 이 항목은 시각적 방향을 보강하는 텍스트 지시로 사용하십시오.

외형은 `프리셋 + 추가 입력`을 함께 쓸 수 있습니다. 아무 프리셋도 고르지 않고 추가 입력도 비워두면 해당 인물의 외형 설명은 생략됩니다. 프리셋은 빠르게 방향을 잡기 좋고, 추가 입력은 세부 보강용입니다.

외형 프리셋은 단순 체형 몇 가지에 그치지 않고 실제 영상에서 자주 쓰는 체형·얼굴 윤곽·헤어스타일을 고르게 제공합니다. 대표적으로 슬림한 체형, 탄탄한 체형, 아담한 체형, 곡선이 도드라진 체형, 허리가 잘록한 모래시계 체형, 볼륨 있는 체형, 큰 키의 늘씬한 체형, 넓은 어깨, 긴 다리, 부드럽고 둥근 얼굴선, 또렷한 턱선, 긴 검은/갈색 머리, 어깨까지 오는 머리, 짧은 단발, 아주 짧은 머리 (픽시컷), 생머리, 웨이브, 곱슬머리, 뒤로 묶은 머리 (포니테일), 땋은 머리, 옅은 주근깨 등이 있습니다. `볼륨 있는 가슴 (성인 전용)`, `작은 가슴 (성인 전용)`처럼 성인 전용으로 표시된 기본 프리셋은 해당 인물의 연령을 `20대` 이상으로 선택했을 때만 목록에서 사용할 수 있습니다.

외형 추가 입력은 자유입력입니다. `아름다운`, `귀여운` 같은 추상적인 미형 평가보다 실제 영상에서 확인할 수 있는 체형·실루엣·머리·얼굴 특징을 구체적으로 적는 편이 효과적입니다. 여러 특징을 쉼표로 함께 적어도 됩니다. 예: `날씬하고 탄탄한 체형, 긴 다리, 긴 검은 머리`. 이 입력칸은 해당 Person A/B/C 본인의 외형을 설명하는 곳입니다. 옆에 있는 동반자, 배경 인물, 별도 사물은 `scene_prompt`, 다른 Person 슬롯 또는 R2V Reference 역할로 지정하십시오. 한국어는 내부적으로 영어로 번역됩니다. 어린이·청소년 연령대에서는 연령에 맞는 중립적인 외형 묘사를 사용하십시오.

의상도 `프리셋 + 추가 입력`을 함께 쓸 수 있습니다. 아무 프리셋도 고르지 않고 추가 입력도 비워두면 해당 인물의 의상 설명은 생략됩니다. 기존 한복·정장·셔츠와 슬랙스·드레스·청바지·운동복·코트·수영복·비키니에 더해 실제 사용자가 자주 찾는 교복, 가디건과 스커트, 블라우스와 청바지, 터틀넥과 슬랙스, 오버사이즈 스웨터, 탱크톱과 반바지 등을 보강했습니다. 그 밖에도 다음처럼 실제 영상에서 자주 쓰는 범위를 제공합니다.

- 교복 / 가디건과 스커트 / 블라우스와 청바지
- 터틀넥과 슬랙스 / 오버사이즈 스웨터 / 탱크톱과 반바지
- 블라우스와 펜슬 스커트 / 비즈니스 캐주얼
- 티셔츠와 청바지 / 니트와 스커트
- 트렌치코트 / 가죽 재킷 / 데님 재킷
- 후드티와 조거 팬츠 / 현대적 스트리트웨어
- 요가복 / 테니스복 / 자전거 라이딩복
- 여름 원피스 (선드레스) / 칵테일 드레스 / 이브닝 가운
- 바디콘 / 오프숄더 / 홀터넥 / 슬립 드레스
- 블라우스와 미니스커트 / 크롭탑과 청바지 / 캐미솔과 쇼츠
- 원피스 수영복 / 비치 커버업
- 누드 (성인 전용)

미성년 보호 규칙은 한 가지입니다. `(성인)` 또는 `(성인 전용)`으로 지정한 기본 외형·의상 프리셋은 그 인물의 연령이 `20대` 이상일 때만 선택할 수 있습니다. `지정 안 함`, `어린이`, `청소년`에서는 해당 항목이 선택 목록에서 빠지며, 성인 전용 항목을 선택한 뒤 연령을 이 세 값 중 하나로 바꾸면 화면의 현재 값은 잠시 `지정 안 함`으로 바뀌지만 이전 선택은 기억됩니다. 다시 `20대` 이상으로 돌아오면 그동안 다른 프리셋을 직접 고르지 않은 경우 이전 성인 전용 선택이 자동 복원됩니다. `수영복`, `비키니`는 일반적인 해변·수영 상황도 고려해 성인 전용으로 분류하지 않습니다.

의상 추가 입력은 프리셋 설명 뒤에 자연스럽게 이어 붙여집니다. 예를 들어 `코트와 스커트` 프리셋에 추가 입력으로 `베이지색 울 코트`를 쓰면 둘을 함께 사용합니다. 의상은 `무엇을 입고 있는가`에 집중합니다. 디테일·화질·렌더링 품질을 강제하는 문구는 이 칸보다 장면 설명에 필요한 만큼 직접 적는 것이 안전합니다. I2VA/FL2VA/L2VA에서는 참조 이미지의 실제 외형·복장과 강하게 충돌하는 설명이 일관성을 낮출 수 있습니다.

외형과 의상은 해당 인물이 실제 진행에서 처음 등장할 때 Person A/B/C 정체성과 함께 한 번 소개되고 이후 진행마다 같은 긴 문장을 반복하지 않습니다.
프리셋은 이미 고정된 canonical 영어 문구이므로 번역기에 다시 보내지 않습니다. 한국어 `추가 입력`만 별도로 영어로 번역한 뒤 프리셋과 마지막에 합칩니다. 따라서 프리셋이 번역 과정에서 변형되거나 약해지는 것을 방지합니다.

어린이와 청소년은 일반적인 영상 장면에 정상적으로 사용할 수 있습니다.
가정, 학교, 운동, 놀이, 가족 영상 등 일반적인 장면 생성을 제한하지 않습니다.

음성 특징은 선택 사항입니다.

예:

- 밝고 부드러운 목소리
- 낮고 차분한 목소리
- 빠르고 명료한 말투

음성 특징은 해당 인물이 실제로 처음 말하는 시점에 H3 화자 ID와 함께 소개되고,
같은 인물의 이후 대사에서는 같은 음성 identity를 유지합니다.


============================================================
13. 시간순 진행 수
============================================================

화면에 펼쳐서 사용할 시간순 진행 칸 수입니다.
각 진행 칸은 같은 시점의 행동·대사 한 묶음입니다. 진행 1은 첫 사건, 진행 2는 다음 사건처럼 사용하십시오. 최종 프롬프트는 여전히 시작 시점 기준으로 정렬되므로 시간이 더 이른 진행 2가 진행 1보다 먼저 출력될 수도 있습니다.

시간순 진행 수는 1~6개이며 최소값은 1입니다.

인물 수와 시간순 진행 수는 서로 다릅니다.

예:

주요 인물 수 = 2
시간순 진행 수 = 5

가능한 사용 예:

1. 진행 1에서 첫 사건 작성
2. 진행 2에서 두 번째 사건 작성
3. 진행 3에서 세 번째 사건 작성
4. 공동 행동·공동 발화가 필요하면 해당 진행의 대상 인물을 여러 인물 선택으로 설정
5. 나머지 진행 칸은 필요에 따라 추가

최종 프롬프트는 진행 번호를 그대로 따라가는 것이 아니라 각 진행의 `시작 시점`을 우선해 다시 정렬합니다.


============================================================
14. 각 시간순 진행 항목
============================================================

각 진행에는 다음 항목이 있습니다.

- 대상 인물
- 시작 시점
- 행동
- 대사
- 대사 언어
- 말하는 방식


[대상 인물]

이 진행에서 행동하거나 말할 사람을 선택합니다.
복합 선택이면 해당 진행의 행동과 대사를 선택된 사람들이 함께 수행합니다.

행동은 한 사람, 대사는 두 사람이 해야 하는 경우에는 진행을 분리하는 것이 안전합니다.

각 진행은 같은 시점에 일어나는 행동과 대사 한 묶음을 의미합니다.

- 진행 1 = 첫 번째로 입력하는 사건
- 진행 2 = 다음 사건
- 진행 3 = 그 다음 사건

대상 인물은 그 사건의 주체를 정하는 항목입니다. 같은 진행에서 대상을 바꾸며 여러 사건을 쌓는 방식이 아니라, 다른 사람의 다른 행동·대사·시점이 필요하면 다음 진행 칸을 사용하십시오.

예를 들어:

- 진행 1 = 인물 1 / 2.0초 / 의자에 앉는다 / "오랜만이야."
- 진행 2 = 인물 2 / 5.0초 / 여자를 바라본다 / "많이 이뻐졌네."

처럼 각각의 진행을 독립된 사건으로 작성합니다.

이 값들은 실제 워크플로우/백엔드 실행 데이터이며, 내용이 있는 진행만 최종 프롬프트 생성에 사용됩니다.


[시작 시점]

영상 시작 후 이 이벤트가 어느 시점 부근에서 시작되기를 원하는지 적습니다.

예:

0.0
1.5
3.0
5.0

이 값은 프레임 단위로 반드시 정확히 실행되는 하드 타임코드가 아닙니다. 최종 프롬프트는 `At approximately 2.00 seconds`처럼 대략적인 기준 시점으로 전달합니다.

우선순위는 다음과 같습니다.

1. 사건의 정상적인 순차 진행
2. 사람과 카메라의 자연스러운 동작 속도
3. 가능한 범위에서 지정한 시작 시점에 근접

UI의 위/아래 조절과 허용값은 0.5초 단위입니다. 최대값은 항상 `영상 길이 - 0.5초`입니다. 예: 10초 → 9.5초, 15초 → 14.5초, 30초 → 29.5초. 영상 길이를 줄였을 때 범위를 넘는 기존 값은 화면에서 새 최대값으로 조정되므로 바뀐 값을 바로 확인할 수 있습니다. 구형 워크플로우나 예외 경로가 범위를 벗어나거나 0.5초 단위가 아닌 활성 진행값을 전달해도 안전하게 해석 가능한 경우 현재 영상 길이 안의 가장 가까운 0.5초 값으로 자동 보정하고 `info` 경고로 알립니다. 시작 시점 자체는 여전히 대략적인 기준점으로 해석됩니다.

시간을 억지로 맞추기 위해 노드가 슬로모션이나 빨리감기를 지시하지 않습니다. 여러 복잡한 행동이나 긴 대사를 지나치게 짧은 간격에 몰아 넣으면 MiniMax H3가 일부 시점을 유연하게 해석할 수 있으므로, 물리적으로 가능한 간격을 주는 것을 권장합니다.

입력 칸의 위아래 순서보다 `시작 시점`이 우선합니다.
백엔드는 모든 활성 사건을 시작 시점 기준으로 자동 정렬합니다.

예:

- 인물 1 = 5.0초
- 인물 2 = 2.0초

이면 최종 프롬프트 순서는 반드시 `2.0초 인물 2 → 5.0초 인물 1`이 됩니다.
인물 번호가 시간 순서를 바꾸지 않습니다.

시작 시점이 완전히 같은 사건은 진행 칸 번호를 안정적인 동률 기준으로 사용합니다. 같은 시각의 여러 사건은 겹치는 행동/발화로 해석될 수 있다는 경고가 표시됩니다.


[행동]

해당 시점에 실제로 일어나는 행동을 자연어로 적습니다.

예:

- 창밖을 바라본다
- 컵을 테이블에 내려놓고 자리에서 일어난다
- 천천히 남성 쪽으로 고개를 돌린다
- walks toward the open doorway

이 노드는 정해진 행동 단어 사전이나 화이트리스트로 행동을 판단하지 않습니다.
영어 행동문은 그대로 사용합니다. 한국어 행동문은 실행 시 영어로 내부 번역하며, 번역 결과는 끝까지 `action`으로 유지되고 `<d>` 대사로 변환되지 않습니다.

한국어 설명 안에서 `인물 1`, `인물 2`, `인물 3`처럼 노드의 인물 번호를 직접 적으면 번역 전에 각각 `Person A`, `Person B`, `Person C` 구조로 보호합니다. 이 규칙은 시간순 진행뿐 아니라 한국어 `전체 장면 / 배경`에도 적용하므로 번역기가 인물 번호를 사람 이름이나 `Figure 1` 같은 다른 의미로 바꾸는 위험을 줄입니다. 단일 인물을 대상으로 하는 시간순 진행 행동에서는 `자신이`, `자신의`, `본인`처럼 선택된 행동 주체를 명백히 가리키는 한국어 재귀 표현도 같은 Person ID로 보호합니다.

단일 인물 시간순 진행 행동에서는 `진행 N 대상 인물`을 한국어 번역의 최종 행동 주체로 사용합니다. 번역 전용 고유 Actor 표식과 Person 참조 표식을 구분하여 전달하므로, `인물 1이 손을 흔든 뒤 ...`처럼 다른 인물이 앞쪽 부사절·조건절에 등장하더라도 선택된 진행 인물의 행동 주체와 다른 Person 참조를 서로 섞지 않도록 합니다. 번역기가 `From far behind, ...`, `After Person A ..., ...`처럼 도입구를 앞으로 옮겨도 특정 문구 허용 목록을 계속 추가하는 대신 Actor 구조를 기준으로 다시 `Person A/B/C` 문장으로 복원합니다. `카메라가 ...`, `장면이 ...`처럼 첫 번역에서 명확한 독립 주어가 유지되는 문장은 그 구조를 존중합니다. 두 번째 외부 번역 요청이 실패하거나 번역 전용 Actor 표식 자체가 사라지면 첫 번역 결과를 그대로 사용하며, 로컬 사전으로 임의의 영어 행동을 만들어내지 않습니다.

이 보호는 인물 번호·재귀 표현·선택된 시간순 진행 주체·성별처럼 노드가 이미 확실히 알고 있는 문법 구조에만 적용합니다. 의상·행동·사물·장소·감정 같은 일반 단어에는 고정 사전이나 강제 치환을 사용하지 않습니다. `그/그녀/he/she/they`처럼 다른 인물을 가리킬 수도 있는 일반 대명사는 문장 중간에서 일괄 치환하지 않습니다. 이렇게 번역 구조만 고정하고 내용 단어는 번역기에 맡깁니다.

H3 본문 품질을 위해 영어 행동문을 가장 권장하지만 한국어 입력도 사용할 수 있습니다. 큰따옴표 안의 실제 화면 글자는 scene 번역과 같은 보호 규칙을 사용합니다.


[대사]

실제로 말할 문장을 입력합니다.
대사 원문은 자동번역하지 않습니다.

예:

오늘은 조금 늦었네.

최종 H3 형식 예:

<d>[Korean] 오늘은 조금 늦었네.</d>


[대사 언어]

기본 `자동`은 한국어/영어를 우선 판별합니다.

- 한국어 대사 → Korean
- 영어 대사 → English

다른 지원 언어도 사용할 수 있습니다.
정확한 태그가 중요하면 사용자가 해당 언어를 직접 선택하십시오.

지원 선택 항목:

- English
- Korean
- Japanese
- Chinese
- Spanish
- French
- German
- Russian
- Arabic
- Italian
- Portuguese


[말하는 방식]

화면 속 인물이 직접 말함:
화면에 보이는 인물이 직접 대사합니다.

화면 밖 음성 (보이스오버):
해당 인물의 목소리가 보이스오버로 재생됩니다.
T2VA에서는 H3 보이스오버 규칙에 맞춰 화면 속 화자의 입술이 닫혀 있어야 한다는 지시를 함께 구성합니다. I2VA/L2VA/FL2VA에서는 참조 이미지 픽셀을 분석하지 않으므로 화면에 해당 인물이 실제로 보인다고 가정하거나 입술 닫힘을 강제하지 않습니다.


============================================================
14-1. T2VA 입력이 완전히 비어 있을 때
============================================================

참조 이미지가 없는 T2VA에서 `장면 설명`가 비어 있고, 표시된 모든 진행의 행동과 대사도 비어 있으면 생성할 실제 장면 내용이 없습니다.

이 상태를 예전처럼 Python 예외로 중단시키지 않습니다. ComfyUI에서는 `h3_prompt` 출력 경로를 조용히 실행 차단하고 `info`에 `status=waiting_for_content`를 남깁니다. 임의의 인물·장면·행동을 대신 만들어 넣지 않습니다.

장면 설명에 장면을 적거나, 진행 1 이상에 행동 또는 대사를 입력하면 정상적으로 H3 프롬프트가 생성됩니다.


============================================================
15. 스타일
============================================================

`원문 / 참조 유지 · 스타일 추가 없음`을 사용하면 노드가 별도의 스타일을 추측해 추가하지 않습니다.

필요한 경우 다음과 같은 스타일을 선택할 수 있습니다.

기본 매체·렌더 계열:

- 시네마틱
- 실사
- 실사 + 시네마틱
- 2D 애니메이션
- 일본 애니 스타일
- 3D CG
- 클레이메이션
- 수채화
- 빈티지 필름

미감·장르 방향까지 포함한 실용 스타일:

- 흑백 시네마
- 필름 누아르
- 다크 판타지
- 시네마틱 공포
- 불길한 어둠
- 포스트 아포칼립스
- 고딕
- 사이버펑크
- 몽환

`2D 애니메이션`은 일반적인 2D 애니메이션 표현을 넓게 지시합니다. `일본 애니 스타일`은 더 구체적으로 2D 선화, 셀 계열 셰이딩, 애니메이션식 장면 연출을 지시합니다. 따라서 두 항목은 일부 겹치지만 목적이 다릅니다.

공포·불길한 어둠은 주로 조명·공간·긴장감을 바꾸고 사용자가 지시하지 않은 괴물이나 사건을 자동으로 만들지 않습니다. 반면 문명 붕괴 이후·사이버펑크·고딕·다크 판타지처럼 배경 세계관이 핵심인 항목은 선택한 장소를 알아볼 수 있게 유지하면서 그 장소의 건축·재료·기반시설·미술 방향을 해당 세계관으로 재해석합니다. 즉 모든 스타일을 단순 색보정 문장으로 취급하지 않습니다.

선택한 스타일은 `[Shot 1]`의 맨 앞에서 강하게 선언되고, 같은 스타일이 모든 Shot과 진행 중 배경 변경까지 유지된다는 문구가 함께 들어갑니다. 그래서 새 배경이 나왔다고 평범한 현대 실사나 원래 배경 스타일로 되돌아가지 않도록 합니다.


============================================================
16. 카메라 움직임
============================================================

기본값은 카메라 지시 없음입니다.

지원 예:

- 카메라 고정
- 화면 확대 / 축소 (줌)
- 카메라 앞으로 / 뒤로 이동
- 카메라 시선 왼쪽 / 오른쪽 회전
- 카메라 왼쪽 / 오른쪽 평행 이동
- 카메라 시선 위 / 아래 이동
- 카메라 수직 상승 / 하강
- 피사체 주위 원호 이동
- 피사체 따라가기
- 약한 / 강한 카메라 흔들림
- 1인칭 시점
- 화면 시계방향 / 반시계방향 회전

카메라 움직임 목록은 MiniMax H3 공식 가이드에 명시된 움직임을 사용합니다. 카메라 움직임을 명시적으로 선택했을 때만 이동 폭과 속도 설정이 의미가 있습니다.

자동 구성에서는 사용자가 명시하지 않은 불필요한 컷을 새로 만들어내지 않는 것을 우선합니다.
약간의 거리·각도 변화만 필요한 경우에는 굳이 새 Shot을 발명하기보다 같은 Shot 안의 자연스러운 카메라 움직임을 사용하는 쪽이 권장됩니다.
현재 실행은 시간순 진행 + 촬영 컷 구조를 사용합니다. scene_prompt에 `||`, `CUT:` 같은 예약 숏 구분자를 직접 넣으면 프롬프트에 섞지 않고 오류로 안내합니다. 명시적 컷은 `여러 촬영 컷 사용`을 켠 뒤 촬영 컷 2~6의 `시작시점(초)`·전환 방식·대상·구도·카메라 움직임으로 설정하세요.


------------------------------------------------------------
16-1. 여러 촬영 컷 사용
------------------------------------------------------------

시간순 진행과 촬영 컷은 서로 역할이 다르지만 직접 연결됩니다.

- `시간순 진행` = 한 영상 안에서 무엇이 언제 일어나는지 정하는 시간 흐름입니다.
- `촬영 컷` = 그 흐름을 어떤 화면/대상/구도로 보여줄지 나누는 H3 Shot입니다.

둘 다 최대 6개까지 사용할 수 있지만 1:1로 강제되지 않습니다. 진행은 행동·대사가 바뀌는 시간축이고 촬영 컷은 카메라가 바뀌는 독립 시간축입니다. 예를 들어 진행이 6개여도 촬영 컷 1개만 끝까지 유지할 수 있고, 진행이 1개뿐이어도 촬영 컷 2를 3.0초, 촬영 컷 3을 7.0초에 시작해 카메라만 여러 번 바꿀 수 있습니다.

기본/초기화 상태:
- 진행 1은 기본으로 존재하고 표시됩니다.
- 촬영 컷 1도 기본으로 존재합니다. `▶ 촬영 설정`을 펼치면 `촬영 컷 1 대상`과 `촬영 컷 1 구도`를 확인할 수 있습니다. 구도 행은 항상 존재하며 비인물 대상에서는 `자동 · 장면에 맞춤`만 사용할 수 있고, 인물/인물 조합 대상에서는 얼굴·상반신·전신 등 인물용 선택지가 열립니다.
- 촬영 컷 1은 영상 시작 0.0초부터 항상 존재하므로 별도의 시작 ON/OFF나 시작시점 입력이 없습니다.

`여러 촬영 컷 사용 = OFF`:
- 촬영 컷 1만 사용합니다.
- `촬영 컷 1 대상`과 `촬영 컷 1 구도`는 OFF 상태에서도 실제 프롬프트에 적용됩니다. 특정 인물을 대상으로 고르면 그 인물의 프로필도 촬영 대상의 시각 정보로 유지됩니다.
- `현재 진행에 맞춤 + 자동 · 장면에 맞춤`은 기존 기본 동작과 동일하며 불필요한 추가 카메라 문장을 만들지 않습니다.
- 자연스러운 영상 생성 흐름이나 카메라 움직임에 추가 Shot 경계를 강요하지 않습니다.

`여러 촬영 컷 사용 = ON`:
- 촬영 컷 2가 기본 활성화됩니다.
- 진행 수가 1이었다면 진행 2까지 사용할 수 있도록 UI가 함께 확장됩니다.
- 촬영 컷 2를 ON으로 켜면 `촬영 컷 2 시작시점(초)`에서 영상 몇 초부터 새 컷을 시작할지 직접 정합니다.
- 촬영 컷 3~6은 앞 촬영 컷이 활성화된 상태에서 `촬영 컷 N 시작 = ON`으로 순서대로 켭니다.
- 촬영 컷 수를 따로 맞추지 않습니다. 활성 촬영 컷 수는 Shot 2~6 ON/OFF 상태에서 자동 계산됩니다.

각 촬영 컷 2~6의 설정:
- `촬영 컷 N 시작`: 이 Shot을 사용할지 ON/OFF
- `촬영 컷 N 시작시점(초)`: 영상 시작 후 몇 초부터 새 Shot을 시작할지 0.5초 단위로 직접 설정
- `촬영 컷 N 전환 방식`: 일반 컷 / 크로스 디졸브 / 페이드 / 와이프
- `촬영 컷 N 대상`: 현재 진행 / 특정 인물 / 인물 조합 / 전체 장면
- `촬영 컷 N 구도`: 구도 행은 항상 표시됩니다. 인물 또는 인물 조합을 대상으로 선택하면 얼굴·상반신·전신·넓은 전경 등을 선택할 수 있고, `현재 진행에 맞춤`/`전체 장면`처럼 비인물 대상에서는 `자동 · 장면에 맞춤`만 사용할 수 있습니다.
- `촬영 컷 N 카메라 움직임`: 새 Shot 안에서의 추가 카메라 움직임
- `촬영 컷 N 카메라 이동 폭`: `기본 설정을 따라감`이면 위의 카메라 이동 폭을 상속, `기본 · 생략`이면 이 Shot의 폭 문구만 생략, `작게`/`크게`는 이 Shot에만 적용
- `촬영 컷 N 카메라 속도`: `기본 설정을 따라감`이면 위의 카메라 속도를 상속, `기본 · 생략`이면 이 Shot의 속도 문구만 생략, `느리게`/`빠르게`는 이 Shot에만 적용

촬영 대상/구도와 대사·세부 외형은 물리적으로 동시에 보일 수 있어야 합니다. 예를 들어 `인물 1 얼굴 클로즈업` Shot에서 인물 2가 `화면 속 인물이 직접 말함`으로 대사하면 입 모양 동기화 조건과 촬영 대상이 충돌할 수 있으므로 info에 경고합니다. 얼굴 클로즈업인데 전신 체형/전체 의상을 확인하려 하거나, 넓은 전경인데 미세한 얼굴/민족적 외형을 확인하려는 경우에도 설정은 프롬프트에서 삭제하지 않지만 가시성 한계를 경고합니다. 이런 경우 필요한 정보를 실제로 볼 수 있는 별도 Shot/구도로 나누는 것이 권장됩니다.

중요: 새 Shot의 시간은 따로 입력하지 않습니다.
`촬영 컷 N 시작시점(초)`에 입력한 값이 그대로 `[Shot N] At 00:SS.mmm`의 영상 전체 기준 절대시간이 됩니다. 시간순 진행의 시작 시점과는 독립적이므로 행동 변화와 카메라 전환을 같은 시각에 맞출 수도 있고 서로 다른 시각으로 설정할 수도 있습니다.

예를 들어 10초 영상에서:

진행 1 = 0.0초
진행 2 = 1.5초
진행 3 = 3.0초
진행 4 = 5.0초
진행 5 = 7.5초

촬영 컷 1 = 기본
촬영 컷 2 시작 = ON
촬영 컷 2 시작시점(초) = 4.5
촬영 컷 2 대상 = 인물 1
촬영 컷 2 구도 = 상반신
촬영 컷 3 시작 = ON
촬영 컷 3 시작시점(초) = 9.0
촬영 컷 3 대상 = 인물 1
촬영 컷 3 구도 = 얼굴 클로즈업
촬영 컷 4 시작 = OFF

이면 개념적인 H3 구조는:

[Shot 1] ... 진행 1~3 ...
[Shot 2] At 00:05.000, ... 진행 4 ...
[Shot 3] At 00:07.500, ... 진행 5 ...

이 됩니다.

촬영 컷 2~6의 시작시점은 반드시 앞 Shot보다 늦어야 하며 0.5초 단위를 사용합니다. 영상 길이보다 0.5초 짧은 값까지 사용할 수 있고, 순서가 뒤집히거나 범위를 벗어나면 traceback 대신 입력을 고치라는 안내로 실행을 막습니다.

촬영 대상은 현재 인원 수에 맞춰 자동 제한됩니다. 한 명이면 현재 진행/인물 1/전체 장면, 두 명이면 인물 1·2 및 조합, 세 명이면 인물 1~3 및 가능한 조합을 사용할 수 있습니다. 인원 수를 줄였다 다시 늘리는 일반 변경에서는 사용자가 입력한 숨은 설정을 보존하고, 다시 활성화될 때 복원합니다.

MiniMax H3에서는 실제 새 피사체·새 시점·새 공간·새 시간 정보처럼 화면을 분명히 나눌 이유가 있을 때 Shot 전환을 사용하는 것이 좋습니다. 같은 인물을 계속 찍으면서 확대하거나 따라가는 정도라면 새 Shot보다 같은 Shot 안의 카메라 움직임을 우선하는 편이 안정적입니다.

전환 방식은 다음 네 가지입니다.
- 일반 컷
- 겹침 전환 (크로스 디졸브)
- 페이드 전환
- 밀어내기 전환 (와이프)

상단 `카메라 이동 폭`과 `카메라 속도`는 단일 촬영에서는 현재 카메라 움직임에 적용되고, 여러 촬영 컷에서는 촬영 컷 1의 값이자 하위 컷의 상속 기본값입니다. 촬영 컷 2~6의 `카메라 이동 폭/속도` 기본값은 `기본 설정을 따라감`이므로 기존처럼 상단 값을 그대로 사용합니다. 특정 Shot만 다르게 만들려면 개별 `작게/크게`, `느리게/빠르게`를 선택하고, 그 Shot에서만 modifier를 없애려면 `기본 · 생략`을 선택합니다. 이 값들은 전환 방식 자체의 속도를 조절하지 않으며, H3에서 폭·속도 modifier가 의미 있는 카메라 움직임에만 적용됩니다.


============================================================
17. 참조 이미지 유지 정도
============================================================

`영상 스타일` 바로 아래에 참조 이미지 관련 설정을 한곳에 모아 표시합니다.

첫 번째 줄은 `참조 이미지 유지 강도`입니다. 자동에서는 실제 이미지 연결 상태로, 수동에서는 선택한 이미지 모드에 필요한 참조가 모두 연결되어 I2VA / FL2VA / L2VA 중 하나가 성립할 때만 자동으로 나타납니다. 수동 T2VA는 이미지가 연결되어 있어도 참조를 사용하지 않으므로 숨겨지고, 수동 이미지 모드에서 필수 참조가 빠진 경우에도 숨겨집니다. 숨겨져도 저장된 선택값은 바뀌지 않습니다.

- 강하게 유지
- 균형
- 변화 허용

두 번째 줄은 `참조 이미지 의상 유지`입니다. 이 옵션은 위 조건보다 좁게, 시작 이미지만 실제 참조하는 I2VA가 성립할 때만 표시됩니다. 자동 모드라도 시작 이미지만 연결되어 실제 동작이 I2VA이면 표시됩니다. 기본값은 `ON`이며, 숨겨졌다 다시 나타나도 사용자가 고른 ON/OFF 값은 유지됩니다.
켜져 있으면 `<Picture 1>`의 의상·색상·소재·액세서리를 영상 전체에서 유지하라는 전역 지시를 추가하고, 인물별 의상 프리셋/의상 추가 입력은 저장만 유지한 채 실행 프롬프트의 의상 변경 지시에서는 제외합니다. 이 기능은 모델 내부의 별도 고정 강도 파라미터가 아니라 프롬프트 지시이므로 실제 생성에서의 유지 정도를 100% 보장하는 기능은 아닙니다.

즉 T2VA에서는 두 줄 모두 숨겨지고, L2VA/FL2VA에서는 `참조 이미지 유지 강도`만 표시되며, 유효한 I2VA에서는 두 줄이 함께 표시됩니다.


============================================================
18. 환경음
============================================================

`환경음`은 다음을 다룹니다.

- 배경의 주변 소리
- 물리적인 동작 소리
- 비언어적인 사람 소리

대사의 실제 문장은 환경음에 반복하지 않습니다.

설정:

자동:
장면과 행동을 바탕으로 보수적인 환경음 구조를 구성합니다.

최소한의 환경음:
과도한 소리를 피하면서 필요한 최소한의 환경음을 사용합니다.

직접 입력한 환경음만 사용:
사용자가 입력한 환경음 힌트를 중심으로 사용합니다.
힌트가 비어 있으면 오류로 알려줍니다. 대사/보이스오버 또는 음악으로 보이는 명백한 문구는 H3 필드 분리 규칙과 맞지 않을 수 있으므로 info 경고를 표시합니다.

환경음·동작음 없음:
주변음·동작음·비언어적 사람 소리를 사용하지 않습니다.
이 설정은 대사나 배경 음악까지 강제로 제거한다는 뜻이 아닙니다.
대사도 없고 배경 음악도 사용하지 않아 영상 전체가 명시적으로 완전 무음인 경우에는 H3 가이드에 맞춰 `overall_soundscape: N/A`를 사용합니다. 대사나 배경 음악이 남아 있으면 전체 무음이 아니므로 `N/A`라고 쓰지 않고 주변음·동작음·비언어 소리가 없다는 영어 문장으로 표현합니다.

최종 overall_soundscape는 H3 구조상 1~4문장 또는 `N/A`로 검사합니다.
사용자가 너무 많은 문장을 넣으면 임의로 잘라내지 않고 오류로 알려줍니다.


============================================================
19. 배경 음악
============================================================

`관객에게만 들리는 음악`은 시청자에게만 들리는 배경 음악(non-diegetic music)을 설정합니다.

예:

- 사용 안 함
- 절제된 피아노 + 저음 현악
- 어쿠스틱 기타 + 베이스
- 잔잔한 신시사이저
- 반복되는 전자 리듬
- 점차 고조되는 오케스트라
- 직접 입력한 음악

직접 입력한 음악를 선택하면 음악 설명을 직접 입력해야 합니다. 악기, 템포/속도, 리듬, 질감, 강약 변화 중심으로 작성하십시오. 추상적인 감정/분위기 기능이나 장면 속 인물이 듣는 diegetic 음악으로 보이는 문구는 info 경고 대상입니다.

최종 시청자용 배경 음악(non_diegetic_music)은 1~3문장 범위로 검사합니다.
초과하면 내용을 임의 삭제하지 않고 오류로 알려줍니다.


============================================================
20. 화면 속 글자
============================================================

전체 장면 / 배경에 큰따옴표로 적은 화면 글자는 자동번역 과정에서 원문 보존 대상으로 처리합니다.

예:

네온 간판에 "OPEN"이라고 적혀 있다.
문에 "영업중"이라고 쓰여 있다.
표지판에는 "A  B"라고 적혀 있다.

따옴표 안의 철자, 구두점, 의도적인 연속 공백을 가능한 한 그대로 유지합니다.


============================================================
21. 예약된 H3 구조를 직접 입력하지 마세요
============================================================

일반 입력란에 다음 구조를 직접 넣지 않는 것이 중요합니다.

- integrated_multimodal_description:
- overall_soundscape:
- 시청자용 배경 음악(non_diegetic_music):
- [Shot 1]
- [Shot 2]
- <d>...</d>

이 구조는 노드가 최종 출력에서 자동으로 생성합니다.
사용자가 일반 행동/장면 입력에 직접 넣으면 중첩되거나 잘못된 H3 구조가 될 수 있으므로 오류로 차단합니다.


============================================================
22. 노드 크기와 씬 입력창
============================================================

`전체 장면 / 배경`은 여러 줄을 입력할 수 있는 기본 ComfyUI multiline 입력창입니다.

사용자가 마우스로 노드의 세로 크기를 직접 늘리면 남는 공간을 씬 입력창이 자연스럽게 사용합니다.
노드를 직접 줄이면 씬 입력창도 함께 줄어듭니다.

주요 인물 수, 시간순 진행 수, 여러 촬영 컷, 촬영 컷별 시작 ON/OFF, 인물 고급 설정처럼 표시 행이 달라지는 항목을 바꿀 때는
ComfyUI/LiteGraph가 계산한 노드 레이아웃 높이를 변경 전과 변경 후에 각각 읽습니다.
그 차이만 현재 사용자가 정해 둔 노드 높이에 즉시 더하거나 빼므로, 씬 입력창은 그대로 두고 노드 하단만 필요한 만큼 늘거나 줄어드는 것이 목표 동작입니다.

이 방식은 다음 원칙을 지킵니다.

- 사용자가 현재 보고 있는 scene_prompt 높이를 기준으로 함
- 위젯 행 높이, 한국어/영어 글자 길이, padding, gap을 자체 공식으로 추정하지 않고 ComfyUI 코어 계산값을 사용함
- 사용자가 수동으로 늘리거나 줄인 노드/씬 입력창 크기를 다음 동적 변경에서도 그대로 보존함
- 최신 ComfyUI의 typed-array node.size를 일반 Array라고 가정하지 않음
- 커스텀 ResizeObserver, setInterval, 지속적인 크기 감시 루프를 만들지 않음
- 빠른 연속 변경에서는 최신 변경만 유효하도록 token으로 이전 확인을 취소함
- 일반 경로에서는 노드 크기를 선제적으로 한 번만 조정함
- 오래되거나 특이한 frontend에서 코어 계산값으로 변화량을 얻지 못한 경우에만 최종 씬 높이를 한 번 확인하고 한 차례만 보정함

따라서 정상적인 최신 frontend에서는 설정 행이 늘거나 줄 때 씬 입력창이 먼저 찌그러졌다가 복원되는 두 단계 움직임을 만들지 않는 것이 목표입니다.

사용자가 노드를 직접 크게 또는 작게 조절했다면 그 뒤 실제로 보이는 씬 높이가 다음 동적 변경의 새로운 기준이 됩니다.
초기 워크플로우 로드에서는 저장된 노드 크기를 억지로 다시 계산하지 않습니다.

23. 실전 예제 — 두 사람이 순서대로 대화
============================================================

전체 장면 / 배경:
저녁의 조용한 공원 산책로. 젊은 여성과 남성이 나란히 천천히 걷고 있다.

장면 설명 번역:
자동 · 한국어→영어 / 영어는 그대로

영상 길이:
8초

주요 인물 수:
2

인물 1:
여성 / 30대 / 밝고 부드러운 목소리

인물 2:
남성 / 30대 / 낮고 차분한 목소리

시간순 진행 수:
3

진행 1
- 대상 인물: 인물 2
- 시작: 1.0초
- 행동: 여성 쪽을 바라본다
- 대사: 오늘 날씨 정말 좋네.
- 언어: 자동
- 방식: 화면 속 인물이 직접 말함

진행 2
- 대상 인물: 인물 1
- 시작: 3.5초
- 행동: 미소를 지으며 고개를 끄덕인다
- 대사: 그러게. 조금 더 걸을까?
- 언어: 자동
- 방식: 화면 속 인물이 직접 말함

진행 3
- 대상 인물: 인물 1 + 2
- 시작: 6.0초
- 행동: 서로를 바라보고 웃는다
- 대사: 좋아.
- 언어: 자동
- 방식: 화면 속 인물이 직접 말함

이 경우 실제 첫 발화자는 인물 2이므로:

- 인물 2 = S1
- 인물 1 = S2
- 마지막 공동 대사 = (S1,S2)

25. 오류가 발생하는 대표적인 경우
============================================================

다음은 자동으로 안전하게 고칠 수 없어 명확히 오류 또는 실행 차단으로 알려주는 항목입니다.

- 영상 길이가 4~30초 정수로 해석될 수 없음
- 숨은 시간순 사건 데이터가 손상되어 해석할 수 없음
- 일반 입력란에 예약된 H3 구조를 직접 삽입함
- 영어 내부 번역이 필요한 한국어 설명(scene/action/sound/music/voice)에서 두 번역 경로가 모두 실패함

경고 문구는 가능한 경우 바로 고칠 수 있는 다음 행동을 함께 안내합니다. `status=` 토큰 자체는 자동화 호환을 위해 기존 값을 유지합니다.

다음 경우는 위의 실행 차단 항목과 다릅니다. 현재 버전은 안전하게 해석할 수 있으면 먼저 정상값으로 보정하고, 필요한 경우 `info`에 이유를 남깁니다.

- 현재 `주요 인물 수` 밖의 진행 대상을 선택함: 활성 인물 범위 안의 대상으로 안전하게 보정하고 `info`에 어떤 대상이 바뀌었는지 남깁니다. 예를 들어 주요 인물 1명 상태에서 진행 대상을 인물 2로 받은 경우 인물 1로 보정합니다.
- `직접 입력한 환경음만 사용`인데 환경음 입력이 비어 있음: 실행을 막지 않고 절제된 자연 환경음·동작음으로 보정합니다.
- `직접 입력한 음악 사용`인데 음악 입력이 비어 있음: 실행을 막지 않고 비다이제틱 배경 음악 없음(`N/A`)으로 보정합니다.
- 사용자 환경음이 H3의 4문장 예산을 넘음: 앞 4문장만 사용하고 `info`에 잘림 경고를 남깁니다.
- 사용자 음악이 H3의 3문장 예산을 넘음: 앞 3문장만 사용하고 `info`에 잘림 경고를 남깁니다. 프리셋 음악에 추가 입력을 붙이는 경우에는 남은 문장 예산 안에서 추가 입력을 줄입니다.
- 진행 시작 시점: 입력/로드 시 가장 가까운 0.5초 단위로 맞추고, 활성 진행이 현재 `영상 길이 - 0.5초`를 넘으면 허용 가능한 최대 시점으로 줄입니다. 진행 수를 줄여 숨겨 두었던 진행을 다시 활성화할 때도 현재 영상 길이에 맞춰 즉시 재보정합니다. Python 백엔드는 같은 규칙을 최종 안전망으로 다시 확인합니다.
- 수동 H3 이미지 모드에서 필수 이미지가 빠짐: 다른 모드로 자동 보정하지 않습니다. I2VA는 시작 이미지, L2VA는 마지막 이미지, FL2VA는 시작+마지막 이미지를 요구하며, 누락 시 최상단 지시어 배지에서 가장 먼저 연결 안내를 표시하고 `h3_prompt`만 `waiting_for_reference` 상태로 조용히 대기합니다. 수동 T2VA는 연결 이미지가 있어도 이를 프롬프트 모드 판정에서 무시합니다.


============================================================
26. info 출력
============================================================

`info`는 최종 영상 프롬프트가 아니라 상태 확인용 출력입니다.

다음과 같은 내용을 확인할 수 있습니다.

- 실제 판별된 H3 모드
- 시간순 진행 사용 여부
- 주요 인물 수
- 실제 활성 시간순 사건 수
- 자동번역 설정
- 품질 권고 또는 실행을 막지 않는 경고
- 사용자 수정이 필요한 경우의 `status=` 상태값과 `warning=` 원인

정상적으로 프롬프트가 생성되면 별도의 `status=` 줄은 붙지 않습니다. 사용자가 설정이나 입력을 고쳐야 해서 프롬프트 출력을 의도적으로 막는 경우에는 아래 공개 상태값 중 하나가 `info`에 표시됩니다. 완전히 빈 Main T2VA 초안과 수동 이미지 모드의 필수 이미지 누락은 현재 배지 안내 흐름을 유지하기 위해 메시지 없는 `ExecutionBlocker(None)`으로 `h3_prompt` 분기만 조용히 대기시키며, ComfyUI native 빨간 입력 오류로 만들지 않습니다. 그 밖의 사용자 입력 오류·번역 실패 등은 기존 처리 경로를 유지합니다. ExecutionBlocker를 사용할 수 없는 환경에서도 빈 `h3_prompt`와 동일한 `info` 상태를 반환합니다. 공개 `status=` 토큰은 일관되게 유지됩니다. 번역 실패의 사람용 `warning=` 문장은 현재 ComfyUI 언어에 맞춰 한국어 UI에서는 한국어, 영어 UI에서는 영어로 표시됩니다.

상태값                                의미 / 사용자가 할 일
--------------------------------------------------------------------------
waiting_for_content                   T2VA에 장면 설명도 없고 활성 시간순 진행의 행동/대사도 없음. 씬 또는 진행 내용을 입력합니다.
waiting_for_reference                 수동 I2VA/L2VA/FL2VA에 필요한 시작/마지막 이미지가 빠짐. 배지에 표시된 이미지를 연결합니다. 다른 모드로 자동 변경하지 않습니다.
waiting_for_valid_profile_selection   성인 전용 기본 외형·의상 프리셋과 선택 연령이 맞지 않음. 20대 이상을 명시적으로 선택하거나 허용 프리셋으로 바꿉니다.
waiting_for_valid_input               안전하게 자동 보정할 수 없는 잘못된 영상 길이, 예약 H3/R2V 마크업 직접 입력, 잘못된 선택값, R2V Reference 계약 위반, 손상된 내부 JSON, 사용자 환경음/음악 힌트 누락 등의 입력 오류. 바로 아래 `warning=` 내용을 고칩니다.
waiting_for_translation               필요한 한국어→영어 번역을 안전하게 완료하지 못함. 네트워크 단절, 번역 서비스의 비정상 응답, 빈/안전하지 않은 결과, 번역용 Person 토큰 무결성 실패처럼 429 이외의 번역 실패를 확인합니다. deep-translator는 선택적 마지막 호환 fallback일 뿐 필수 설치 항목이 아닙니다.
waiting_for_translation_rate_limit    Google/MyMemory 번역 경로가 HTTP 429 또는 provider cooldown 상태임. 표시된 cooldown/Retry-After가 지난 뒤 다시 시도합니다. 반복 429에서는 대기 시간이 점진적으로 늘고 그 상태는 ComfyUI 재시작 후에도 유지됩니다. 번역이 꼭 필요하지 않으면 `사용 안 함 · 입력 그대로`를 선택할 수 있으며, 이 경우 모든 비대사 서술의 온라인 번역 요청이 발생하지 않습니다.

이 `status=` 값들은 워크플로우나 자동화 파이프라인에서 분기용으로 사용할 수 있는 공개 상태값으로 취급합니다. 구체적인 사람용 설명은 같은 `info`의 `warning=` 줄을 확인하십시오. 반대로 컴파일러/렌더러 내부에서 정상이라면 절대 발생하지 않아야 하는 불변조건 실패나 프로그래밍 오류는 이 상태값으로 감추지 않고 예외로 남겨 실제 버그를 발견할 수 있게 합니다.

실제 MiniMax H3에 전달할 프롬프트는 `h3_prompt` 출력을 사용하십시오.

27. 권장 작성 원칙
============================================================

1) 전체 장면 / 배경에는 공통 설정을 적습니다.
2) 시간에 따라 바뀌는 행동과 대사는 시간순 진행에 적습니다.
3) 같은 행동을 장면과 진행에 중복해서 반복하지 않는 것이 좋습니다.
4) 설명문은 영어가 가장 권장됩니다. 한국어 scene은 씬 자동번역 기본값을 사용하고, 한국어 행동·환경음·배경음악·외형·복장·음성 특징은 내부 번역됩니다.
5) 대사는 번역되지 않으므로 실제로 말하게 할 원문을 그대로 적습니다.
6) H3 화자 번호는 직접 관리하지 말고 노드에 맡깁니다.
7) 실제 동시 발화는 여러 인물 선택 인물을 사용합니다.
8) 영상 길이는 실제 H3 생성 길이와 맞춥니다.
9) 이미지 입력은 이 노드와 실제 H3 생성 노드에서 같은 참조 흐름을 사용하는 것이 좋습니다.
10) 지나치게 많은 행동과 긴 대사를 짧은 영상에 몰아넣지 않는 것이 좋습니다.

28. 중요 제한 사항
============================================================

이 노드는 규칙 기반 프롬프트 컴파일러입니다.

할 수 없는 것:

- 참조 이미지의 얼굴이나 배경 분석
- 이미지 안의 인물이 누구인지 자동 판단
- 사용자가 쓴 장면의 모든 의미적 모순을 AI처럼 이해해 수정
- MiniMax H3 실제 생성 결과를 미리 보장

할 수 있는 것:

- H3 구조에 맞춰 장면/행동/대사/소리/음악 정리
- 이미지 연결 상태에 따른 H3 입력 방식 판별
- 시간순 진행 검증
- 최초 실제 발화 순서 기반 S ID 자동 배정
- 복합 화자 ID 구성
- 한국어 scene/action/sound/music/voice 설명의 영어 내부 번역 (대사 제외)
- 화면 글자 보호
- 잘못된 구조와 명백한 입력 오류 차단

29. 문제 해결
============================================================

[한국어 UI가 나오지 않을 때]
ComfyUI의 `Locale / Language` 설정이 한국어인지 확인하고 화면을 새로 고치십시오.
이 노드는 브라우저 언어를 기준으로 강제로 한국어로 바꾸지 않습니다.

[영어 UI인데 일부 한국어이 남을 때]
이전 커스텀 노드 파일이 덮어쓰기로 남아 있지 않은지 확인하십시오.
기존 폴더를 삭제한 뒤 배포 폴더를 새로 복사하고 ComfyUI를 재시작하는 것이 가장 확실합니다.

[한국어 설명 번역이 실패할 때]
인터넷 연결을 확인하십시오. 대사는 원래 번역 대상이 아니므로 영향을 받지 않습니다. `장면 설명 번역`을 `사용 안 함 · 입력 그대로`로 바꾸면 전체 장면 / 배경뿐 아니라 진행 행동, 환경음, 배경 음악, 인물 외형·복장·음성 특징, R2V Reference 설명·적용 지시어 등 모든 비대사 서술의 온라인 번역을 함께 건너뛰고 입력을 그대로 사용합니다. 자동 상태에서도 이미 영어인 입력은 번역 요청 없이 그대로 사용됩니다.

[인물 2가 먼저 말했는데 S1이 아닌 것처럼 보일 때]
현재 사용 중인 커스텀 노드 폴더가 최신 배포본인지 확인하십시오. 정상 동작에서는 실제 첫 대사 인물이 S1입니다.

[옵션 변경 후 노드 높이가 이상할 때]
설치 폴더를 덮어쓰기하지 말고 기존 `comfyui-Ultra-MiniMax-H3-Prompt` 폴더를 삭제한 뒤 배포 폴더를 새로 복사하십시오.
그 다음 ComfyUI를 완전히 재시작하고 브라우저를 새로 고치십시오.
Vue Nodes에서는 인물 수나 시간순 진행 수를 바꾸는 순간 multiline 입력창이 짧게 재배치될 수 있습니다. 정상 상태라면 곧바로 변경 전 씬 입력창 높이로 복원되고, 외부 노드 높이가 새 옵션 구성에 맞게 정리됩니다. 계속 다른 높이로 남거나 매번 누적해서 커지거나 줄어든다면 설치된 JS가 최신본인지 먼저 확인하십시오.

- 판별된 모드, 활성 설정, 경고를 확인하는 진단용 문자열


끝.


============================================================
인물 수 변경과 진행 데이터 보존
============================================================

`주요 인물 수`를 1, 2, 3 사이에서 변경하면 인물 프로필 입력란의 표시 여부만 바뀝니다. 인물 2/3의 기본값과 고급값은 숨겨질 뿐 삭제되지 않으므로 다시 인원 수를 늘리면 이전 값이 복구됩니다.

예를 들어 인물 수를 3 → 1 → 3으로 변경해도 각 `진행 N`에 이미 입력한 대상 인물, 시작 시점, 행동, 대사, 대사 언어, 말하는 방식은 다른 진행이나 다른 인물 값으로 섞이지 않습니다.

인물 수를 줄여 현재 존재하지 않는 인물을 대상으로 지정한 진행은 실행 전에 대상 선택이 유효한 인물로 조정될 수 있으므로, 실제 생성 전에는 각 진행의 `대상 인물`을 확인하십시오. 인물 1의 프로필 행은 인물 수가 1 이상이면 항상 표시되어야 합니다.


미성년 보호 설명 메모: 보호 규칙은 하나뿐입니다. 노드에서 `성인`/`성인 전용`으로 정한 기본 외형·의상 프리셋은 인물 연령이 `20대` 이상일 때만 선택할 수 있습니다. 그 외 연령에서는 해당 선택지가 목록에서 빠지고 현재 값은 잠시 `지정 안 함`이 되지만, 이전 선택은 기억되었다가 다시 `20대` 이상으로 돌아오면 복원됩니다. 중간에 사용자가 다른 프리셋을 고르면 그 새 선택을 우선합니다. `수영복`과 `비키니`는 성인 전용으로 분류하지 않습니다. 자유입력 장면 설명와 외형/의상 추가 입력은 이 기능이 분석하거나 수정하지 않습니다.

성인 전용으로 분류된 기본 외형·의상 프리셋은 화면에서 선택할 때와 실제 실행할 때 같은 보호 기준을 사용합니다. 연령 조건이 맞지 않으면 실행 전에 사용자 안내가 표시됩니다.


[장면 설명만 사용하는 경우의 인물 프로필]
진행 수가 활성화되어 있어도 실제 진행 행동·대사를 비워 두고 장면 설명만 사용하는 경우가 있습니다. 이때도 현재 활성 인물에서 사용자가 직접 고른 성별·연령·외형·의상은 최종 H3 프롬프트에 포함됩니다. 아무것도 선택하지 않은 기본 인물 프로필을 임의로 만들어 넣지는 않습니다. 실제 진행 행동/대사가 있으면 인물 프로필은 처음 필요한 위치에서 한 번 충분히 소개되고, 그 뒤의 진행에서는 `Person A/B/C` 중심으로 간결하게 이어집니다. 따라서 같은 `a young woman in her twenties...` 같은 인물 프로필 정보가 매 행동·대사마다 반복되어 행동·시간·카메라 지시를 불필요하게 밀어내지 않습니다. 연령을 `지정 안 함`으로 두고 성별만 고른 경우도 `여성→woman`, `남성→man`, `남성·여성 이외 (논바이너리)→non-binary person`으로 반영됩니다.


외형·의상 기본 프리셋의 연령 보호는 화면 선택과 실행 검증에서 동일한 기준을 사용합니다. 실행 전에 연령 조건을 한 번 최종 확인합니다.

복수 촬영을 사용할 때 대사 길이 검사는 영상 전체의 남은 시간만 보지 않습니다. 현재 대사가 들어간 Shot에서 **다음 Shot 시작 시점까지 남은 시간**을 기준으로 확인하며, 마지막 Shot에서만 영상 끝까지의 남은 시간을 사용합니다. 일반적인 발화 속도 추정으로 경계에 가까우면 기존처럼 경고만 표시합니다. 그러나 매우 빠른 발화 속도를 보수적으로 가정해도 다음 Shot 또는 영상 끝 전에 끝낼 수 없는 것이 명백하면 `waiting_for_valid_input`으로 실행을 차단합니다. 대사 원문이나 Shot 시간은 자동 변경하지 않습니다.


[H3 컷을 넘는 대사]
MiniMax H3 공식 가이드는 한 대사가 컷을 넘어 계속될 때 `<scenetrans>`, 영상 끝에서 말이 잘릴 때 `<cutoff>`를 사용하도록 설명합니다. 이 노드는 사용자의 대사를 임의로 둘로 나누거나 `<scenetrans>`/`<cutoff>`를 자동 삽입하지 않습니다. 대신 경계에 가까운 경우에는 경고하고, 매우 빠른 발화로도 물리적으로 들어가기 어려운 경우에는 실행을 차단하여 사용자가 대사 시작 시점·Shot 경계·대사 길이를 직접 조정하도록 합니다. 해당 태그의 직접 입력은 계속 예약 구조로 차단합니다.


============================================================
31. 별도 노드: Ultra MiniMax H3 Prompt R2V
============================================================

이 패키지에는 `Ultra MiniMax H3 Prompt`와 별도로 다음 노드가 포함되어 있습니다.

- Ultra MiniMax H3 Prompt R2V

중요: R2V는 메인 노드의 `영상 입력 방식(mode)`이 아니라 별도 노드입니다.
메인 노드는 T2VA / I2VA / L2VA / FL2VA를 담당하고, R2V는 별도 Reference 입력과 프롬프트 흐름을 사용합니다.
두 노드는 한 워크플로우 안에서 서로의 모드나 입력값을 직접 변경하지 않습니다.

R2V는 메인 노드와 독립적으로 동작합니다.


------------------------------------------------------------
31-1. 왜 R2V를 별도 노드로 만들었나요?
------------------------------------------------------------

MiniMax H3의 일반 T2V/I2V 계열과 Full Reference R2V(Ref2VA)는 단순히 같은 모드의 옵션 하나가 아닙니다.
Ref2VA는 이미지·비디오·오디오를 함께 사용하면서 "어느 참조에서 무엇을 가져올 것인가"를 프롬프트 안에서 명확히 정의해야 합니다.
또한 실제 생성 모델도 H3-Base-Ref2VA 계열을 사용하므로 기존 T2VA/I2VA/L2VA/FL2VA 조건 분기에 억지로 합치지 않았습니다.

R2V 노드는 다음 사용자 기능을 함께 제공합니다.

- 전체 장면 / 배경
- 0~3인 목표 인물 (0명은 환경·사물·제품·비인물 중심 R2V)
- 인물 프로필
- 최대 6개 시간순 진행
- 최대 6개 촬영 컷
- 대사와 S-ID
- 환경음
- 배경 음악
- 한국어 설명의 영어 번역 경로

Reference 관계와 최종 출력 형식은 R2V 전용 구조를 사용합니다.
R2V 최종 프롬프트의 최상위 기준은 MiniMax 공식 `skills/h3-prompt-writing/SKILL.md`와 그 파일이 지시하는 `references/ref-en.txt` / `VIDEO_PROMPT_WRITING_GUIDE_ref_en.md`의 Full Reference 규칙입니다.


------------------------------------------------------------
31-2. 처음 보이는 Reference 입력 단자
------------------------------------------------------------

노드를 처음 추가했을 때 MiniMax H3 최대 입력 수를 전부 펼쳐 놓지 않습니다.
처음에는 다음과 같은 최소 Reference 연결구만 보입니다.

- Picture 1
- Video 1
- Video 1 Audio
- Audio 1

Picture의 마지막 빈 단자에 이미지를 연결하면 Picture 2가 나타납니다.
다시 Picture 2를 연결하면 Picture 3이 나타나는 방식으로 필요한 만큼만 한 개씩 늘어납니다.

Video도 같은 원리로 Video 1을 사용하면 다음 Video 연결구가 추가됩니다.
`Video N Audio`는 그 Video와 함께 전달할 동기화된 원본 soundtrack용 입력입니다.
독립된 음성·효과음·음악 파일은 `Audio N`에 연결합니다.

중요: 이 프롬프트 노드의 `Video N`은 원본 Reference Video의 duration/관계/역할을 확인하기 위해 `VIDEO` 객체를 받습니다. 반면 현재 공식 로컬 ComfyUI의 MiniMax H3 Reference-to-Video 생성 경로에서 `ref_video_N`이 `IMAGE` 프레임 배치를 받는 구성이라면 같은 영상을 두 갈래로 나눠 연결해야 합니다. `Load Video`의 `VIDEO`는 이 프롬프트 노드의 `Video N`으로 보내고, 같은 VIDEO를 `Get Video Components`에 넣어 `images` 출력은 실제 H3 생성 노드의 `ref_video_N`으로, 원본 soundtrack을 사용할 때는 `audio` 출력을 이 노드의 `Video N Audio` 및 생성 경로의 대응 오디오 입력으로 연결합니다. 즉 이 프롬프트 노드의 `VIDEO` 단자를 생성 노드의 `IMAGE` Reference 입력에 직접 연결하는 구조가 아닙니다.

연결을 제거하면 남은 Reference 연결이 앞 번호로 정리됩니다.
예를 들어 Picture 1을 제거하고 기존 Picture 2만 남으면 그 연결은 새 Picture 1이 됩니다.
이때 그 Reference에 지정했던 참고할 요소·반영 방식·원본 내용·특징·결과 반영 방법도 연결과 함께 이동하도록 설계했습니다.

백엔드는 ComfyUI V1이 공식 지원하는 동적 입력용 flexible optional dictionary를 사용합니다.
따라서 새 R2V 노드는 처음부터 Picture 1 / Video 1 / Video 1 Audio / Audio 1만 실제 단자로 만들고, 연결할 때 필요한 다음 단자만 추가합니다. 최대 개수의 빈 단자를 먼저 만든 뒤 JS로 접는 과정이 없으므로 새 노드 삽입이나 워크플로우 전환 때 불필요하게 긴 초기 노드가 나타나지 않습니다. 동적으로 만든 연결값은 그대로 Python 실행의 kwargs로 전달됩니다.

R2V도 기존 메인 노드처럼 맨 아래에 `기본 보기 / 전체 설정 보기`와 `설정 초기화` 동작을 가지며, 두 동작 모두 ComfyUI 기본 버튼 위젯을 사용합니다.
R2V 새 노드와 `설정 초기화` 직후는 **기본 보기 + 모든 그룹 접힘** 상태입니다. 기본값은 주요 인물 수 1명 / 시간순 진행 수 1개지만, 해당 선택기는 `▶ 기본 설정`을 펼쳐야 보입니다. 인물 설정은 `▶ 인물 1`, 진행 설정은 `▶ 진행 1`을 각각 펼쳐 확인합니다. R2V는 필요할 때 `주요 인물 수=0`도 선택할 수 있어 환경·사물·제품 중심 작업을 지원합니다. 인원 수나 진행 수를 줄여도 일반 변경에서는 해당 행의 값과 허용된 일반 외부 연결 기억을 보존하고, 다시 늘리면 복원합니다. Reference를 연결하면 해당 Reference 그룹이 `전체 장면 / 배경` 바로 아래에 추가되며 다른 그룹과 마찬가지로 `▶/▼`로 독립적으로 접고 펼칠 수 있습니다. 하단 `기본 보기 / 전체 설정 보기`는 그룹 접힘과 독립입니다.
중요: R2V 기본 화면에 `시간순 진행 수`가 보이더라도 Timeline은 필수 입력이 아닙니다. Reference 또는 장면 지시만으로 충분한 작업이라면 Timeline 행동·대사를 비워 두어도 됩니다.
한글 UI에서는 `auto`, `none`, `unspecified`, `on_screen` 같은 내부 canonical 값이 그대로 노출되지 않고 한글 표시값으로 보이며, 영어 UI에서는 영어 표시값으로 보입니다. 저장되는 실제 값은 기존 canonical 값 그대로이므로 프롬프트 생성과 워크플로우 호환성에는 영향을 주지 않습니다.
기본 보기 상태에서 `주요 인물 수`나 `시간순 진행 수`를 바꿔도 기본 보기는 그대로 유지되며, 새로 활성화된 인물/진행 그룹의 핵심 행만 추가됩니다. `여러 촬영 컷 사용` ON/OFF도 기본 보기에서 바로 설정할 수 있으며, ON하면 활성 촬영 컷의 시작시점·대상·구도와 바로 다음 촬영 컷 ON/OFF가 순차적으로 나타납니다. 촬영 컷별 전환 방식·개별 카메라 움직임·개별 이동 폭·속도가 필요할 때만 `전체 설정 보기`로 전환합니다.
`설정 초기화`는 두 번 클릭 확인 방식입니다. Picture/Video/Audio Reference 미디어 연결 자체는 유지하면서 Reference 역할/내용 설정, 일반 resettable 설정값과 기억을 기본 상태로 돌리고 모든 그룹을 접습니다. 사용자가 조절한 `전체 장면 / 배경` 입력 높이는 유지하며, 사라지는 고정 설정 행만큼 노드 외곽 높이만 줄어듭니다. 실제 Picture/Video/Audio Reference 선은 그대로 남습니다.


------------------------------------------------------------
31-3. R2V Reference 수와 기본 제한
------------------------------------------------------------

현재 R2V 노드는 MiniMax H3 Ref2VA 공식 규격을 기준으로 다음 한도를 사용합니다.

- Reference Image: 최대 9개
- Reference Video: 최대 3개
- 독립 Reference Audio: 최대 3개
- Video N Audio: 같은 번호 Video에 딸린 soundtrack 입력으로 최대 3개 Video에 각각 사용 가능하며, 독립 Audio 3개 한도를 소비하지 않음
- 이미지 + 비디오 + 독립 오디오 source file 합계: 최대 12개
- 생성 영상 길이: 4~15초
- Audio만 연결한 R2V: Ref2VA 계약상 허용하지 않으므로 Picture 또는 Video Reference를 하나 이상 함께 연결해야 합니다. 반대로 외부 Reference를 하나도 연결하지 않고 사용자가 scene/timeline만 직접 작성한 reference-free 초안은 허용하며, 이때는 외부 Reference가 없다는 중립적인 안내만 `info`에 남습니다.

중요: UI에는 위 물리 한도보다 뒤 번호의 역할 지정용 연결구가 추가로 나타날 수 있습니다. 이것은 10번째 고유 Picture나 4번째 고유 Video를 허용한다는 뜻이 아닙니다. **이미 연결한 같은 실제 파일을 다른 역할로 한 번 더 연결**하기 위한 역할 재사용 전용 연결구입니다. 이 노드는 실제 upstream 객체를 기준으로 먼저 dedupe한 뒤 고유 물리 파일 수를 검사합니다. 9/3/3 또는 혼합 12파일 한도를 넘으면 `waiting_for_valid_input`으로 실행을 차단하며, 같은 실제 파일을 여러 semantic role로 재사용한 것은 한 물리 파일로만 계산합니다.

Reference Video와 Reference Audio의 2~15초 범위는 권장값이 아니라 MiniMax H3 Ref2VA의 공식 입력 제한입니다. Reference Video 전체 합계는 15초 이하여야 합니다. 이 노드에서는 공식 ComfyUI의 분리된 입력 구조에 맞춰 Video N Audio soundtrack 그룹과 독립 Audio 그룹의 확인 가능한 길이 합계를 각각 15초 이하로 검사합니다.
이 노드는 ComfyUI 표준 VIDEO 객체가 제공하는 duration과 표준 AUDIO의 waveform/sample_rate처럼 길이를 안전하게 확인할 수 있는 경우에만 이 제한을 자동 검사합니다. 같은 실제 media를 여러 역할에 재연결한 경우에는 하나의 clip으로만 계산합니다. 확인 가능한 Reference가 공식 2~15초 범위 또는 해당 그룹의 확인 가능한 총 15초 한도를 넘으면 `waiting_for_valid_input`으로 실행을 차단하고, 사용자가 Reference 길이를 조정하도록 안내합니다. Video 없이 단독 연결된 `Video N Audio`는 독립 Audio와 같은 길이 예산에 포함되며, 같은 번호 Video와 짝지어진 soundtrack은 별도 video-soundtrack 그룹으로 검사합니다.
커스텀 loader처럼 duration 정보를 안정적으로 얻을 수 없는 객체는 호환성을 위해 길이만으로 차단하지 않습니다. 이 경우에는 사용자가 실제 Ref2VA 입력 media가 공식 2~15초/총 15초 제한을 지키는지 직접 확인해야 합니다. 노드는 원본 media를 임의로 자르거나 길이를 변경하지 않습니다.

scene_prompt와 시간순 진행의 행동/대사가 비어 있어도 Picture/Video/Audio Reference가 연결되어 있으면 R2V 자체는 실행할 수 있습니다. 이때 노드는 일반 T2V의 빈 내용 차단 규칙을 변경하지 않고, R2V 내부에서만 중립적인 Reference 기반 골격을 만든 뒤 선택한 Reference 역할·반영 방식·원본 내용·결과 반영 방법을 실제 지시의 기준으로 사용합니다. 보이지 않는 원본 특징을 임의로 만들어 넣지는 않습니다. Reference가 하나도 없어도 사용자가 직접 scene_prompt/Timeline 내용을 채웠다면 reference-free 초안으로 프롬프트를 생성할 수 있습니다.


------------------------------------------------------------
31-4. Video N Audio와 Audio N의 차이
------------------------------------------------------------

`Video 1 Audio`는 Video 1과 같은 원본 비디오에 들어 있던 소리를 Ref2VA에 함께 전달하고 싶을 때 사용하는 입력입니다.
Video 화면만 참조하고 원본 소리는 참조하지 않을 때는 연결하지 않아도 됩니다.

`Audio 1`, `Audio 2` 등은 비디오와 별개로 넣는 독립 Reference Audio입니다.

중요: 공식 ComfyUI MiniMax H3 Reference-to-Video 노드는 `Video N Audio` soundtrack 입력(최대 3)과 독립 `Audio N` 입력(최대 3)을 별도 그룹으로 제공합니다. 따라서 같은 번호 Video에서 분리한 soundtrack은 독립 Audio 3개 슬롯을 소비하지 않습니다. 기본적으로는 같은 번호 Video와 함께 쓰는 것이 공식 흐름이며 source-file 12개 계산에서도 같은 Video의 일부로 처리합니다. 다만 이 프롬프트 노드에서는 사용 편의를 위해 `Video N Audio`만 단독 연결해도 초안을 생성하고, `info`에 해당 soundtrack이 독립 오디오 스타일 cue처럼 취급되었다는 경고를 남깁니다.

중요: `<Video N>` 번호와 `<Audio N>` 번호는 서로 짝 번호가 아닙니다.
R2V의 Audio 번호는 ComfyUI H3가 Reference를 전달하는 순서에 맞춰 독립적으로 계산합니다.

1) 연결된 각 Reference Video의 활성 soundtrack
2) 독립 Audio Reference

순서로 `<Audio 1>`, `<Audio 2>`...가 정해집니다.
따라서 `<Video 1>`의 soundtrack이 항상 `<Audio 1>`이라고 단정해서 수동 번호를 관리하면 안 됩니다.
이 번호는 노드가 실제 연결 상태에서 자동 계산합니다.


------------------------------------------------------------
31-5. Reference를 연결한 뒤 지정하는 역할과 관계
------------------------------------------------------------

Reference가 실제로 연결되면 해당 파일마다 R2V 전용 설정이 나타납니다.

Reference 그룹을 `▼`로 펼쳤을 때 기본 보기에서 사용하는 핵심 항목:
- 참고할 요소 : 이 이미지·영상·오디오에서 최종 영상에 무엇을 참고할지 선택
- 반영 방식 : 선택한 원본 요소를 그대로 유지할지, 일부만 참고할지, 전달할지 선택
- 적용 구간 : 어느 Shot에 이 Reference를 사용할지 지정

해당 Reference 그룹을 펼친 상태에서 전체 설정 보기로 전환하면 추가되는 항목:
- 같은 대상 연결 / 오디오 대사 화자 지정 : 필요한 경우 Reference 관계를 더 세밀하게 지정
- 원본 내용·특징 : 연결한 원본에서 실제로 보이거나 들리는 사실을 설명
- 결과 반영 방법 : 위 원본 요소를 최종 영상에 어떻게 반영할지 추가로 설명

`원본 내용·특징`과 `결과 반영 방법`은 의미가 다릅니다.

원본 내용·특징 = 원본 파일에 실제로 보이거나 들리는 사실
예: "긴 검은 머리, 흰 블라우스, 은색 귀걸이"
예: "카메라가 인물을 중심으로 천천히 시계 방향으로 도는 움직임"
예: "낮고 차분한 여성 음색, 느린 말하기 속도"

결과 반영 방법 = 그 원본 요소를 최종 영상에서 어떻게 사용할지
예: "얼굴 정체성과 머리 모양은 유지하고 의상은 바꿔도 됨"
예: "카메라 궤적만 참고하고 원본 인물 외형은 가져오지 않음"
예: "음색과 말투만 참고하고 원본 대사 내용은 복사하지 않음"

긴 문장을 입력해야 할 때는 `원본 내용·특징`과 `결과 반영 방법` 왼쪽의 STRING 입력 단자에 ComfyUI Text/String 출력 노드를 연결할 수 있습니다.
- Text 노드를 연결하지 않으면 지금처럼 노드 안의 한 줄 입력칸을 그대로 사용합니다.
- Text 노드를 연결하면 연결된 문자열이 해당 `원본 내용·특징` 또는 `결과 반영 방법` 값으로 우선 사용됩니다.
- 따라서 긴 설명 때문에 R2V 노드 자체를 세로로 크게 만들 필요가 없습니다.
- 인원 수·진행 수·촬영 컷 활성 상태·기본/전체 보기 전환은 이 Text 연결을 제거하지 않습니다.
- 해당 Picture/Video/Audio Reference 자체를 연결 해제하면 그 Reference에 딸린 Text 연결 단자도 함께 정리됩니다. 다시 Reference를 연결하면 노드 안에 직접 입력해 두었던 참고할 요소·원본 내용·특징·결과 반영 방법은 복원되지만, 제거된 외부 연결선은 사용자가 필요할 때 다시 연결해야 합니다.
- 타입은 명확히 분리됩니다. 이 프롬프트 노드의 `Picture N`은 `IMAGE`, `Video N`은 `VIDEO`, 독립 `Audio N`은 `AUDIO` 전용이며 `Video N Audio`는 `AUDIO` 전용입니다. 영상의 내장 오디오는 `Load Video → Get Video Components → audio → Video N Audio` 순서로 연결합니다. 현재 공식 로컬 H3 생성 노드가 Reference Video를 `IMAGE` 프레임 배치로 받는 구성에서는 같은 `Load Video`를 분기해 `Get Video Components → images`를 생성 노드의 `ref_video_N`에 연결하십시오. 프롬프트 노드의 `Video N=VIDEO`와 생성 노드의 Reference-frame 입력은 역할이 다릅니다.

이 구분은 중요합니다. 이 노드는 연결된 이미지/비디오/오디오의 실제 내용을 AI로 판독하지 않으므로, 사용자가 적지 않은 얼굴·장면·사물·대사를 임의로 지어내지 않습니다. 의미가 분명한 정체성·환경·스타일·카메라·음향 역할인데 `원본 내용·특징`이 비어 있으면 실행 자체를 막지는 않지만 info에 안내 경고를 남겨, 공식 Context-IR식 상세 설명에 필요한 원본 사실이 부족하다는 점을 알려 줍니다.


`반영 방식`은 MiniMax H3 Full Reference의 공식 Reference 관계를 사용합니다.

Visual Reference:
- 자동
- fully_preserved : 참조 특성을 완전히 보존
- partially_preserved : 핵심 특성은 유지하되 목표 변경 허용
- attribute_transfer : 참조 특성을 지정한 목표 인물로 전달
- weak_reference : 넓은 분위기/특성만 약하게 참고

Audio Reference:
- 자동
- fully_copy : 오디오 전체 신호를 최종 신호로 그대로 사용
- partially_copy : 요청한 일부 구간/레이어만 복사
- reference : 음색·리듬·질감 같은 특성만 참조
- weak_reference : 넓은 오디오 분위기만 약하게 참고

`자동`은 선택한 참고 요소와 목표 설정에 맞는 안전한 반영 방식을 선택합니다. 예를 들어 얼굴/정체성은 기본적으로 보존을 강하게 해석할 수 있지만, 사용자가 같은 인물의 목표 외형을 별도로 지정해 둔 기존 설정이 있으면 자동 관계는 충돌을 일으키지 않도록 `partially_preserved`로 완화하고 info에 경고합니다. 반대로 사용자가 직접 `fully_preserved`를 선택한 경우에는 그 관계가 더 높은 권위를 가지므로 모순되는 외형·의상·스타일·카메라 설정을 그대로 동시에 보내지 않고 오류로 알려줍니다.

`적용 구간`은 Auto / 모든 Shot / 현재 존재하는 개별 Shot / 여러 Shot 조합에서 Reference가 실제 효력을 갖는 구간을 정합니다. 예를 들어 Shot 1과 Shot 3에만 등장하는 Reference는 `Shot 1 + Shot 3`처럼 비연속 조합으로 지정할 수 있습니다. 존재하지 않는 Shot 3/4를 선택할 수 있게 남겨 두지 않으며, 뒤쪽 촬영 컷을 OFF하여 기존 범위가 잠시 사라지면 안전한 Auto로 대체했다가 다시 유효해졌을 때 이전 선택을 복원합니다. 인물 2/3용 역할도 현재 인원 수에 맞춰 제한하고 인원 수를 다시 늘리면 이전 역할을 복원합니다.

Picture의 대표 역할:
- 인물 1/2/3 정체성·외형
- 인물 1/2/3 의상
- 인물 1/2/3 포즈·표정
- 장면 / 환경
- 동물 / 비인물 주체
- 시각 스타일
- 사물 / 제품 / 소품
- 시각 효과 / VFX
- 화면 글자 / 인터페이스
- 실제 첫 프레임 기준
- 실제 중간 키프레임 기준
- 편집할 원본 키프레임
- 실제 마지막 프레임 기준
- 실제 프레임 / 구도 기준
- 스토리보드 / 촬영 계획
- 일반 참조 / 직접 지정

Video의 대표 역할:
- 인물 1/2/3 정체성·외형
- 인물 1/2/3 의상
- 인물 1/2/3 동작·연기
- 장면 / 환경
- 동물 / 비인물 주체
- 사물 / 제품 / 소품
- 시각 효과 / VFX
- 화면 글자 / 인터페이스
- 카메라 움직임
- 컷·속도·시간 리듬
- 움직이는 영상 스타일
- 직접 편집할 원본 Video
- 이어 만들 원본 Video
- 일반 참조 / 직접 지정

Video에서 사람·의상·환경·물체 같은 "보이는 내용"을 가져올 때는 최종 프롬프트에서 `<Subject N>` 관계로 정리합니다. `<Video N>` 자체는 원본 Video 전체의 카메라·컷·시간 구조·직접 편집·이어 만들기와 같은 whole-video 관계에 사용합니다.

Audio의 대표 역할:
- 인물 1/2/3 음색·말투·delivery
- 독립 내레이터 음색·말투 (화면 인물 0명 또는 인물과 함께 사용 가능)
- 음악 스타일·악기 질감
- 효과음 질감
- 박자·리듬·타이밍
- 오디오 연속성 / 전환
- 정확한 대사 / 가사 내용
- 오디오 전체 신호 재사용
- 오디오 일부 신호 재사용
- 일반 참조 / 직접 지정

대사/가사 내용 Reference의 `원본 대사·가사`에는 원본 단어와 원래 언어를 정확히 적습니다. 확실하지 않은 부분은 `[unclear]`처럼 표시할 수 있습니다. 이 Reference Audio의 문구가 최종 `<d>`에 직접 사용될 때는 MiniMax Full Reference 공식 규칙에 따라 일반 문장부호만 남기고 반복 물결표·이모지·불릿·반복/장식 문장부호를 정리합니다. 이것은 사용자가 시간순 진행에 직접 입력한 대사와는 다른 규칙입니다. Timeline 직접 대사는 단어와 구두점을 그대로 보존합니다. 음색만 참조하는 역할에서는 원본 대사를 목표 대사로 자동 복사하지 않습니다.

정확한 대사/가사 `원본 대사·가사`를 입력했다면 `적용 구간`과 실제 Timeline 대사도 서로 맞아야 합니다. `자동`에서는 `원본 대사·가사`와 실제 문구가 일치하면서 아직 다른 정확 대사 Audio가 차지하지 않은 첫 발화에 연결합니다. 정확 대사 역할을 고르면 `대사 화자 지정`에서 자동 또는 A/B/C 조합/내레이터를 지정할 수도 있습니다. 따라서 같은 Shot에서 인물 A의 원문은 Audio 1, 인물 B의 원문은 Audio 2처럼 서로 다른 실제 Audio에 정확히 대응시킬 수 있습니다. 서로 다른 유효 발화를 대상으로 하는 정확 대사 Audio는 여러 개 사용할 수 있으며, 같은 발화를 모순되게 중복 점유하는 경우만 차단합니다. `모든 Shot` 또는 특정 Shot을 직접 지정했다면 그 범위에서 정확한 원문 재사용 지시를 받는 모든 대사/가사 문구가 `원본 대사·가사` 안에 실제로 포함되어 있어야 합니다. 예를 들어 `원본 대사·가사`가 `안녕하세요.`뿐인데 Shot 1은 `안녕하세요.`, Shot 2는 `다시 만나요.`이고 `모든 Shot`을 선택하면 서로 다른 Shot 2 대사까지 같은 원본 Audio 문구라고 선언하지 않고 `waiting_for_valid_input`으로 알려줍니다. 여러 Shot의 원문을 하나의 Audio가 실제로 모두 담고 있다면 `원본 대사·가사`에 해당 전체 원문을 함께 적으면 됩니다. `원본 대사·가사`를 비워 둔 경우에는 기존 Timeline 대사를 권위 있는 문구로 사용합니다.

또한 R2V의 6개 섹션과 `<Subject N>`, `<Picture N>`, `<Video N>`, `<Audio N>` 같은 Reference 라벨은 노드가 자동 관리하는 예약 구조입니다. 장면·행동·대사·인물 설명·Reference 자유입력 칸에 이런 구조를 직접 적으면 내부 구조와 충돌할 수 있으므로 실행 전에 사용자 입력 오류로 안전하게 차단합니다.

`화면 글자 / 인터페이스` 역할의 `원본 화면 글자·UI`도 MiniMax 공식 규칙에 따라 번역하지 않습니다. 실제 화면에 보이는 글자나 UI 라벨을 원래 언어 그대로 적어 두면 영어 구조문 안에서도 해당 화면 글자 자체는 원문을 유지합니다.

R2V에서는 "Reference 1의 모든 것을 무조건 복사"하는 것보다 어떤 속성을 어느 대상/Shot/Audio 구간에 어떤 강도로 적용하는지가 더 중요합니다.
예: Picture 1 = 얼굴 fully_preserved, Picture 2 = 의상 attribute_transfer, Video 1 = 동작 partially_preserved, Video 2 = 카메라 weak_reference, Audio 1 = 음색 reference.

각 연결 행은 여전히 하나의 명시적인 `참고할 요소`만 고르지만, **같은 실제 파일을 서로 다른 참고 요소용 연결구에 반복 연결**할 수 있습니다. 노드는 같은 upstream 객체를 하나의 `<Picture N>`, `<Video N>`, `<Audio N>`으로 인식하고 사용자가 직접 선택한 역할만 합칩니다. 예를 들어 같은 Video 하나를 `인물 동작 + 카메라 움직임 + 컷/리듬`에 연결하거나, 같은 Audio 하나를 `인물 음색 + 정확 대사`에 연결해도 물리 파일은 하나로 계산합니다. 노드는 미디어 내용을 보지 못하므로 선택하지 않은 보조 역할을 임의로 추측하지는 않습니다.


비인물 Visual Reference에는 `같은 대상 연결`을 사용할 수 있습니다. 같은 제품의 정면/측면/후면 사진, 같은 장소의 여러 각도, 같은 동물의 사진+영상처럼 여러 소스가 **실제로 하나의 대상**을 설명할 때 Shared 1~6 중 같은 그룹을 지정하면 하나의 `<Subject N>`으로 합칩니다. 장면/환경과 소품처럼 서로 의미가 다른 역할을 억지로 같은 그룹에 넣으면 차단합니다. 같은 대상 그룹 안에서도 어떤 소스는 fully_preserved, 다른 소스는 partially_preserved처럼 관계나 적용 Shot이 다르면 retention에 `<Picture N>=...`, `<Video N>=...` 형태로 소스별 계약을 보존하여 강도 차이를 잃지 않습니다.

Timeline의 화자 선택에는 `내레이터`가 추가됩니다. 화면 인물이 0명인 풍경·제품·다큐 영상에서도 내레이션을 사용할 수 있고, 화면에 인물 A/B/C가 있는 상태에서도 별도의 보이지 않는 내레이터를 시간순 Timeline에 섞을 수 있습니다. 인물이 있는 일반 내레이터 진행에서는 행동 칸을 화면 밖 내레이터의 동작으로 만들지 않고 대사와 필요 시 `독립 내레이터 음색` Audio를 사용합니다. 다만 `주요 인물 수=0`인 비인물 R2V에서는 진행 행동을 제품·사물·동물·환경 같은 보이는 대상의 행동으로 사용할 수 있으며, `rolls slowly`처럼 주어가 생략된 명백한 동사 조각은 중립적인 보이는 대상으로 문법 보완해 사용합니다.

기존 T2V/I2V에서 가져온 장면·인물·Timeline·Camera·Dialogue·환경음·음악 설정은 R2V에서도 목표 영상 지시로 유용하므로 유지합니다. 새 R2V 노드는 Main과 같은 기본 작업 흐름을 위해 주요 인물 수 1명 / 시간순 진행 수 1개로 시작합니다. 환경·사물·제품·비인물 중심 작업이 필요하면 사용자가 주요 인물 수를 0명으로 명시적으로 내릴 수 있으며, 다시 1~3명으로 올리면 일반 변경 중 기억된 인물/진행 설정과 연결을 복원합니다. 다만 Reference가 fully_preserved인 영역은 Reference가 더 높은 권위를 가집니다. 반대로 해상도, sampler, scheduler, shift, `ref_image_size` 같은 실제 추론 설정은 프롬프트 규칙이 아니므로 이 노드에 넣지 않고 실제 MiniMax H3 Ref2VA 생성 노드에서 설정합니다.


------------------------------------------------------------
31-6. 노드가 자동으로 차단하는 Reference 충돌
------------------------------------------------------------

다음과 같이 목적이 서로 충돌하거나 Reference 관계가 성립하지 않는 설정 중 일부는 여전히 실행을 차단합니다. 반면 사용자가 단순히 초안 프롬프트를 보고 싶어 할 수 있는 경우는 이제 차단 대신 `info` 경고로만 안내합니다. R2V에서 정말 차단이 필요한 구조 오류가 남아 있더라도 더 이상 이유 없는 조용한 차단으로 끝내지 않습니다. ComfyUI가 ExecutionBlocker 메시지를 지원하는 환경에서는 `Execution Blocked: ...` 형태로 실제 원인을 화면에 표시하고, `info`에도 같은 `warning=` 원인을 남깁니다. Timeline/Camera의 0.5초 단위 위반처럼 기존 H3 컴파일러가 `waiting_for_*` 상태로 멈춘 경우도 R2V가 그 원인을 메시지 있는 차단으로 전달합니다.

실행을 차단하지 않는 대표 예시
- Picture/Video 없이 Audio만 연결: Ref2VA 계약 위반이므로 실행 차단. Picture 또는 Video Reference를 하나 이상 함께 연결
- Video N은 없는데 Video N Audio만 연결: 독립 오디오 스타일 cue로 취급하고 경고
- 정확 대사/가사 Audio가 현재 Timeline의 실제 발화와 맞지 않음: 경고
- 음색 Audio가 지정되었지만 현재 Timeline에 그 화자의 실제 발화가 없음: 경고
- 인물 수보다 높은 Person 대상 역할을 임시로 지정함: 경고

계속 차단하는 구조 충돌/공식 입력 한도 예시
- 고유 물리 Reference가 Picture 9 / Video 3 / 독립 Audio 3 / 혼합 12 한도를 넘음
- 길이를 확인할 수 있는 Reference media가 공식 2~15초 또는 해당 그룹의 확인 가능한 총 15초 한도를 넘음
- 직접 편집할 원본 Video를 두 개 이상 지정
- Video 편집과 Video 이어 만들기를 동시에 지정
- 이어 만들 원본 Video를 두 개 이상 지정
- 실제 첫 프레임 기준 Picture를 두 개 이상 지정
- 실제 마지막 프레임 기준 Picture를 두 개 이상 지정
- 완전히 1:1로 재사용할 최종 Audio를 두 개 이상 지정
- 최종 Audio 전체 재사용과 다른 Audio Reference를 동시에 지정
- Audio 전체 신호 1:1 재사용(fully_copy)과 별도의 목표 대사·명시적 환경음·독립 배경음악을 동시에 지정
- 하나의 인물에 서로 다른 음색 Reference Audio를 두 개 이상 지정
- 동일한 실제 Timeline 발화를 서로 다른 정확 대사 Audio가 모순되게 중복 점유

하나의 인물에 얼굴 Picture와 의상 Picture, 동작 Video, 음색 Audio를 함께 붙이는 것처럼 서로 보완하는 여러 Reference는 정상적으로 사용할 수 있습니다.


------------------------------------------------------------
31-7. R2V 최종 프롬프트 구조
------------------------------------------------------------

복합 Reference가 많을 때도 같은 all-shots 참조 설명을 Shot마다 장문 반복하지 않고 continuation 문장을 합치며, retention은 역할·관계·적용 범위 중심으로 압축합니다. Shot 3 전용 의상/정체성 같은 좁은 참조는 Shot 1의 첫 등장 설명에 미리 새지 않도록 해당 Shot에서만 적용합니다. 또한 A+B/A+B+C 공동 행동처럼 **컴파일러가 직접 결합한 복수 주어**에는 Main/R2V 공통의 좁은 문법 보정이 적용되어 `Person A and Person B walks` 또는 `<Subject 1> and <Subject 2> walks` 같은 형태를 `walk`로 고칩니다. 임의의 사용자 문장 전체를 다시 쓰는 방식이 아니라, 컴파일러가 만든 복합 주어 action clause 안에서 구조상 확인 가능한 첫 서술어와 병렬 서술어만 제한적으로 교정하며, 목적어·명사 병렬이나 일반 사용자 문장을 전역적으로 수정하지 않습니다.

R2V는 기존 T2V/I2V의 `integrated_multimodal_description` 구조를 그대로 사용하지 않습니다.
최종 `h3_prompt`는 MiniMax H3 Full Reference 형식에 맞춰 정확히 다음 순서로 구성합니다.

1) subject_definitions
2) summary
3) retention_analysis
4) detailed_description
5) overall_soundscape
6) non_diegetic_music

Reference 관계에는 필요에 따라 다음 태그가 사용됩니다.

- <Subject N>
- <Picture N>
- <Video N>
- <Audio N>

`summary`에는 실제 역할에 맞춰 다음과 같은 작업 관계가 들어갈 수 있습니다.

- reference generation
- keyframe completion
- video editing
- video continuation
- audio reuse
- audio reference

Reference 유지 관계에는 H3 Full Reference 규칙의 다음 표현을 사용합니다.

Visual:
- fully_preserved
- partially_preserved
- attribute_transfer
- weak_reference

Audio:
- fully_copy
- partially_copy
- reference
- weak_reference

단순히 태그만 나열하지 않고 `어느 Reference의 어느 특성을 어느 Subject/Shot/Audio 관계에 적용하는지`를 자연어 문장으로 정리합니다.
`retention_analysis`에는 가능한 경우 실제 `[Shot N]` 등장/적용 범위를 적고, `detailed_description`에서도 Reference label을 Shot 1 앞에 한꺼번에 몰아넣지 않고 실제 처음 보이거나 효력이 발생하는 Shot/Audio 구간에 배치합니다.
`subject_definitions`에는 참조 출처와 화면의 `원본 내용·특징`에 적은 사실 정보를 반영하고, `retention_analysis`와 실제 Shot에는 선택한 `반영 방식`·`적용 구간`·`결과 반영 방법`을 반영합니다.

여러 Shot을 쓰는 R2V에서 `scene_prompt`를 빈 줄로 나눈 명백한 시간 단계(예: `At first...` / `Then...` / `By the end...`)로 작성하고 Timeline 행동도 여러 Shot에 걸쳐 있다면, 후반 사건 전체를 Shot 1에 미리 몰아넣지 않고 각 단계가 실제 재생 순서의 Shot에 들어가도록 정리합니다. 반대로 한 문단짜리 일반 장면 설명, 단순한 여러 문단 묘사, 시간 단계가 명확하지 않은 글, 여러 Shot에 걸친 행동 진행이 없는 경우에는 기존 장면 입력을 임의로 쪼개지 않습니다.


------------------------------------------------------------
31-8. 시간순 진행 / 촬영 컷 / 대사
------------------------------------------------------------

R2V에서도 시간순 진행과 촬영 컷 방식을 사용할 수 있습니다.

- 최대 6개 시간순 진행
- 최대 6개 촬영 컷
- [Shot 1]
- [Shot 2] At 00:03.000,
- 최초 실제 발화 순서 기반 S-ID
- <d>[Language] 실제 대사</d>

영상 길이는 공식 Ref2VA 범위에 맞춰 4~15초로 제한합니다.
각 진행 시작 시점과 촬영 컷 2~6 시작시점은 모두 0.5초 단위로 설정합니다. 촬영 컷 시간은 진행 시간과 독립적이며, 촬영 컷 2~6은 현재 영상 길이의 `끝 - 0.5초` 안에서 앞 Shot보다 늦은 시각을 사용해야 합니다.

대사는 번역하지 않습니다.
예를 들어 한국어 대사는 최종 프롬프트에서도 `<d>[Korean] ...</d>` 안에 원문으로 유지합니다.
Reference Audio를 `인물 1 음색`으로 지정한 경우에도 원본 Audio의 대사를 억지로 새 대사로 복사하라고 하지 않고, 음색과 말투만 참조하도록 구분합니다.
`대사/가사 내용 참조` 또는 Audio 재사용 역할은 이와 별도로 사용합니다.

인물 여러 명이 동시에 말하는 A+B / A+B+C 그룹 대사와 그룹 voice-over도 안정적인 전역 S-ID를 사용합니다. R2V의 독립 내레이터까지 포함해 실제 영상에서 처음 발화하는 순서대로 S1, S2...를 한 번만 배정하며, 내레이터가 Person A보다 먼저 말하면 내레이터가 S1이고 Person A는 그 다음 번호를 받습니다. 이렇게 정해진 번호는 detailed_description과 화자에 연결된 <Audio N> 정의에서 동일하게 재사용합니다.
`대사/가사 내용 참조`를 선택했다고 해서 노드가 Reference Audio를 자동 전사하는 것은 아닙니다. 원본 발화 내용을 직접 재사용하려면 사용자가 시간순 진행의 대사에 실제 원문과 원래 언어를 정확히 입력해야 하며, 노드는 그 대사 구간과 `<Audio N>` 관계를 묶어 줍니다.


------------------------------------------------------------
31-9. 한국어 번역
------------------------------------------------------------

R2V Full Reference의 구조적 설명은 영어로 컴파일합니다.
한국어로 장면·행동·인물 추가 설명·환경음·음악·Reference 상세을 입력할 수 있습니다.

- 전체 장면 / 배경: 기존 scene 번역 경로 사용
- 시간순 행동: 기존 내부 번역 경로 사용
- 인물 추가 설명: 기존 내부 번역 경로 사용
- 환경음 / 음악 힌트: 기존 내부 번역 경로 사용
- Reference `원본 내용·특징`/`결과 반영 방법`: 같은 안전한 한국어→영어 번역 helper 사용 (단, 정확한 대사/가사와 `원본 화면 글자·UI`는 번역하지 않음)
- Timeline 직접 대사: 단어·구두점을 번역/재작성하지 않고 원문 그대로 유지
- Reference Audio 정확 대사/가사: 원본 단어·언어는 유지하되 Full Reference 규칙에 따라 장식/반복 문장부호만 제한적으로 정규화

R2V에서도 `장면 설명 번역` 설정을 제공하며 Main과 동일하게 대사를 제외한 비대사 자유입력의 온라인 번역을 함께 제어합니다. 구조적 6개 섹션의 섹션명과 형식 자체는 영어로 유지되지만, `사용 안 함 · 입력 그대로`를 선택하면 각 섹션에 들어가는 한국어 장면·행동·인물 설명·환경음/음악 힌트·Reference 설명/적용 지시어는 번역하지 않고 입력 그대로 사용할 수 있습니다.
영어 입력은 번역 요청 없이 그대로 사용합니다.

MiniMax 공식 Full Reference 가이드는 일반적인 generation 작업의 `detailed_description`을 보통 약 350~500 English words 수준으로 충분히 구체적으로 작성하도록 설명합니다. 그러나 입력 정보가 적은데 숫자만 맞추려고 모델이 보지 못한 장면 사실을 임의로 만들어 넣는 것은 더 위험합니다. 반대로 모든 Shot에 적용되는 동일 인물 정체성·의상·환경·소품의 `원본 내용·특징/결과 반영 방법`을 Shot마다 그대로 반복하는 것도 불필요하게 프롬프트를 길게 만듭니다. 따라서 전체 영상 공통 Reference의 상세 내용은 `subject_definitions`과 `retention_analysis`에 한 번 명확하게 두고, 이후 Shot에서는 해당 `<Subject N>` 관계를 간결하게 재사용합니다. `info`에는 전체 프롬프트 문자 수와 detailed_description 단어 수를 표시하며, 350~500 단어 범위에서 크게 벗어나거나 전체 프롬프트가 7000자를 넘으면 경고만 표시합니다. 7000자 경고는 일부 MiniMax API 경로의 제한을 참고한 것으로 로컬 ComfyUI 런타임을 임의로 차단하지는 않습니다.


------------------------------------------------------------
31-10. 실제 MiniMax H3 R2V 생성 노드와 연결
------------------------------------------------------------

`Ultra MiniMax H3 Prompt R2V`는 프롬프트를 만드는 노드입니다.
Reference Image/Video/Audio를 직접 H3 conditioning으로 변환하거나 Ref2VA 모델을 로드하지 않습니다.

따라서 실제 워크플로우에서는 같은 Reference source를 다음 두 곳에 맞춰 연결합니다.

A) Ultra MiniMax H3 Prompt R2V
- 어떤 파일이 Picture/Video/Audio 몇 번인지
- 어떤 역할을 할 것인지
- 어떤 프롬프트 관계를 만들 것인지 결정

B) 실제 ComfyUI MiniMax H3 Reference-to-Video / Ref2VA 생성 경로
- 같은 Picture/Video/Audio 실제 데이터를 H3 모델에 전달

그리고 R2V 노드의 `h3_prompt` 출력을 실제 Ref2VA 생성 노드의 `prompt` 입력으로 연결합니다.

두 노드에서 Reference의 연결 순서를 맞추는 것이 중요합니다.
R2V 프롬프트의 `<Picture 1>`, `<Video 1>`, `<Audio 1>`이 실제 생성 노드가 받는 같은 번호의 Reference와 일치해야 합니다.

실제 R2V 모델은 H3-Base-Ref2VA 계열을 사용해야 합니다.
기존 T2V/I2V용 H3-Base-FL2VA 계열을 단순히 R2V처럼 사용하는 구조로 설계하지 않았습니다.


------------------------------------------------------------
31-11. R2V 노드가 자동으로 알 수 없는 것
------------------------------------------------------------

이 노드는 규칙 기반 프롬프트 컴파일러이며 VLM/음성 인식/Video 분석기가 아닙니다.

따라서 다음은 자동 판독하지 않습니다.

- Picture 속 사람이 누구인지
- Picture의 실제 의상 종류
- Video 안의 실제 동작
- Video의 정확한 카메라 움직임
- Audio 안의 실제 발화 문장
- Audio의 실제 가수/화자 정체성

사용자가 Reference의 역할을 지정하면 노드는 그 선언을 H3가 이해하기 좋은 Subject/Picture/Video/Audio 관계와 retention 관계로 정리합니다.
참조 파일의 실제 내용과 사용자가 지정한 역할이 맞는지는 실제 입력 파일을 준비하는 사용자가 확인해야 합니다.


------------------------------------------------------------
31-12. Ultra MiniMax H3 Prompt와 R2V의 독립성
------------------------------------------------------------

R2V는 메인 노드의 `mode`가 아니라 별도 노드로 동작합니다.
메인 노드는 T2VA/I2VA/L2VA/FL2VA 판정과 4~30초 범위, Timeline/Camera/Dialogue 구조를 담당합니다.

R2V 노드는 독립적인 Reference 입력과 `참고할 요소 / 반영 방식 / 원본 내용·특징 / 적용 구간 / 결과 반영 방법` 설정, 4~15초 타이밍 제한을 사용합니다.
Main과 R2V는 서로 독립된 UI 상태를 사용합니다.
한 워크플로우 안에서 Main과 R2V를 함께 사용해도 서로의 모드나 입력값을 직접 변경하지 않습니다.

[R2V 노드 레이아웃]
R2V의 `scene_prompt`는 기존 I2V/T2V 메인 노드와 같은 크기 유지 원칙을 사용합니다. 새 노드의 기본 보기에서는 씬 지시어가 필요 이상으로 세로로 늘어나지 않고 간단한 입력 높이로 시작합니다. 사용자가 씬 지시어 높이를 직접 늘이거나 줄인 뒤 주요 인물 수, 시간순 진행, 촬영 컷, Reference 연결 등을 바꾸더라도 그 씬 지시어 높이는 그대로 유지됩니다. 새로 보이거나 숨는 고정 설정 행의 높이만큼 노드 전체 아래쪽이 늘어나거나 줄어듭니다. 따라서 사용자에게 맞춘 씬 입력 높이를 인원 수 변경 때문에 다시 잃지 않습니다. 반복적인 크기 보정 루프나 별도의 전체 높이 공식은 사용하지 않고 ComfyUI/LiteGraph의 실제 위젯 레이아웃 차이를 이용합니다. 초기 값은 주요 인물 1명 / 시간순 진행 1개이며, 실제 Person 1과 진행 1의 행은 각각 `▶ 인물 1`, `▶ 진행 1` 그룹을 펼쳤을 때 Main과 같은 흐름으로 표시됩니다. 사용자가 0명으로 내렸다가 1명 이상으로 다시 올리는 일반 변경에서는 숨겨진 설정과 연결 기억을 복원하며, 설정 초기화에서만 그 기억을 폐기합니다.

- `영상 참조 N 오디오`는 `AUDIO` 전용입니다. 표준 연결은 `Load Video` → `Get Video Components` → `audio` 출력 → `영상 참조 N 오디오` 입니다. 즉 비디오 원본 파일의 사운드트랙을 참조하려면 같은 VIDEO 출력을 오디오 단자에 직접 꽂지 말고, 공식 분리 노드에서 추출한 `audio`를 연결합니다.

[입력 오류와 빈 초안 대기 상태]
- 전체 장면 / 배경은 글자 수가 아니라 실제 내용 유무로 판정합니다. `걷고 있다`처럼 짧아도 공백이 아닌 내용이면 정상입니다. 공백·스페이스·줄바꿈만 있는 값은 빈 입력입니다.
- T2V에서 전체 장면 / 배경·명시적 환경 설정·모든 활성 시간순 진행의 행동/대사가 전부 비어 있어도 ComfyUI native validation으로 Queue를 거부하지 않습니다. `h3_prompt` 출력만 조용히 대기하고 `info`에 `status=waiting_for_content`를 남깁니다.
- R2V도 장면·유효 Reference·시간순 진행 내용이 모두 없는 완전 빈 초안은 같은 `waiting_for_content` 대기 상태입니다. 반면 Audio-only Ref2VA, Reference 물리 한도 초과, 잘못된 예약 구조 등 실제 계약 오류는 계속 실행을 차단합니다.
- 외부 STRING 연결은 실행 전 빈 위젯 표시값만 보고 누락으로 판정하지 않습니다. 연결 자체를 입력 근거로 인정하여 false positive를 막습니다.
- 빨간 ComfyUI native validation은 완전 빈 초안이 아니라 실제로 잘못된 입력/구조가 있을 때의 오류 표시로 이해하면 됩니다.

[R2V 기본 화면 및 설정 초기화]
- 새 R2V 노드와 설정 초기화 직후에는 주요 인물 수 1, 시간순 진행 수 1의 Basic View를 사용하며 모든 그룹은 ▶(접힘) 상태입니다.
- 장면 설명 번역과 기본 설정은 `▶ 기본 설정`, 카메라/다중 촬영 컷은 `▶ 촬영 설정`을 펼친 뒤 사용합니다. 촬영 컷 구도 행은 항상 존재하며 비인물 대상에서는 `자동 · 장면에 맞춤`만, 인물/인물 조합 대상에서는 인물용 구도 선택지를 사용할 수 있습니다.
- 새 노드에서는 `▶ 인물 1` 그룹부터 펼쳐야 인물 1의 행이 보입니다. 기본 보기에서는 성별·연령대·민족적 외형을 바로 사용할 수 있고, 외형/의상/음성 같은 고급 세부 항목은 전체 설정 보기로 전환한 뒤 `○ 인물 1 고급 설정`을 펼쳐 사용합니다. 기본/전체 보기 전환과 `▶/▼ 인물 1` 그룹 접힘은 서로 독립입니다.
- 인원/진행 수를 줄였다 다시 늘리거나 촬영 컷을 OFF했다 다시 ON하는 일반 변경은 기존 설정과 외부 STRING 연결 기억을 유지합니다. 설정 초기화만 그 기억을 폐기합니다.
- 설정 초기화는 진행 1을 포함한 설정 위젯의 외부 STRING 연결을 모두 해제합니다. 일반 인원/진행/촬영 컷 변경에서만 연결 기억/복원을 사용하며, R2V의 Picture/Video/Audio Reference 미디어 연결은 초기화 후에도 유지됩니다.


[R2V 기본 보기와 초기화]
- R2V는 Ref2VA 전용 노드이므로 Main처럼 실제 `영상 입력 방식`을 선택하지 않습니다. 다만 Main과 초기 화면의 공통 행 위치를 맞추기 위해 같은 자리에 `영상 입력 방식 : R2V Reference (고정)`을 표시합니다. 이 행은 JS 전용 표시 항목으로 backend 입력·프롬프트·직렬화·연결에 관여하지 않습니다. 실제 R2V 동작은 연결된 Picture/Video/Audio Reference와 각 Reference 역할을 기준으로 합니다.
- R2V 기본 보기에서 이 항목들은 각 그룹 안에 존재합니다. `▶ 기본 설정`에서는 장면 설명 번역, 고정 영상 입력 방식 표시, 영상 길이/스타일, 기본 장면·날씨, 주요 인물 수/시간순 진행 수를 볼 수 있습니다. `▶ 인물 N`은 모든 활성 인물의 성별·연령대·민족적 외형, `▶ 진행 N`은 모든 활성 진행의 대상·시작 시점·행동·대사만 남깁니다. `▶ 촬영 설정`은 카메라 움직임과 촬영 컷 1 대상·구도를 표시하며, `여러 촬영 컷 사용`을 켜면 활성 촬영 컷의 시작시점·대상·구도와 다음 촬영 컷 ON/OFF가 순차적으로 나타납니다. `▶ 사운드`는 환경음/배경 음악 대표 모드를 남깁니다. 촬영 컷 1의 기본 이동 폭·속도와 촬영 컷별 전환 방식·개별 카메라 움직임·개별 이동 폭·속도는 전체 설정 보기에서 사용합니다.
- 진행 1 행동/대사와 씬 지시어 등 설정 위젯의 외부 연결은 `설정 초기화`에서 해제됩니다. 반면 인원/진행 수를 줄였다 다시 늘리거나 촬영 컷을 OFF했다 다시 ON하는 일반 변경에서는 기존 연결 기억/복원 계약을 그대로 유지하며, R2V의 Picture/Video/Audio Reference 미디어 연결은 초기화해도 유지합니다.


[촬영 컷 시간 이해하기]
- `촬영 컷 2 시작`을 ON으로 하면 두 번째 카메라 Shot이 시작됩니다. 반드시 장소가 바뀌는 것은 아니며 같은 장면에서 전신→상반신처럼 구도만 바꿀 수도 있습니다.
- `촬영 컷 N 시작시점(초)`은 실제 영상 시간(초)입니다. 0.5초 단위로 입력하며 진행의 `시작 시점(초)`과 별개입니다.
  예: `촬영 컷 2 시작시점(초) = 6.5`이면 진행 번호와 관계없이 영상 6.5초부터 촬영 컷 2가 시작됩니다.
- 진행의 시간과 촬영 컷은 역할이 다릅니다. 진행은 행동·대사의 시간축이고, 촬영 컷은 카메라 전환의 독립 시간축입니다. 두 시각을 같게 맞추면 행동 변화와 컷 전환이 동시에 일어나고, 다르게 두면 한 진행 안에서도 카메라만 따로 바꿀 수 있습니다.


[영상 환경 타임라인 - 장면/배경 + 날씨/환경]
- 기본 설정에 "기본 장면 / 배경", "기본 날씨 / 환경"이 추가됩니다. 실제 선택 목록은 장면/배경 65개, 날씨/환경 25개이며 기본 메뉴와 진행 메뉴가 같은 canonical 목록을 공유합니다. 둘 다 `선택 안 함`이면 별도의 장면/날씨 지시를 추가하지 않습니다.
- 각 진행 N에는 "장면 / 배경 변경", "날씨 / 환경 변경"이 같은 실제 프리셋 목록을 공유하여 표시됩니다. 진행 메뉴만 "현재 ... 유지"와 "기본 ... 으로 복귀" 제어값이 앞에 추가됩니다.
- "현재 ... 유지"는 직전까지 적용 중인 상태를 그대로 이어갑니다. "기본 ... 으로 복귀"는 영상 시작의 기본 상태로 돌아갑니다. 새 프리셋을 선택하면 그 진행 시점부터 바뀌고, 이후 진행에서 다시 변경할 때까지 유지됩니다.
- 진행 1이 0.0초에서 기본 장면/날씨를 덮어쓰면 두 상태를 연속으로 적지 않고 진행 1의 값이 실제 영상 시작 상태가 됩니다. 같은 값을 다시 선택한 경우에도 거짓 변화 문장을 만들지 않습니다.
- 장면 프리셋은 이미지용 배경 태그가 아닙니다. 장소의 영상적 특징과 필요한 핵심 움직임만 구체적으로 포함하며, 만원 지하철의 차체 흔들림, 거센 파도의 물결, 가동 중인 설비처럼 장면을 성립시키는 움직임도 현실적인 실시간 속도로 제한합니다.
- 날씨는 단일 선택형입니다. 몰아치는 비바람, 천둥·번개 폭우, 강한 눈보라, 거센 돌풍, 짙은 안개, 모래폭풍처럼 복합적인 강한 기상도 하나의 검증된 영상 프리셋으로 제공합니다. 서로 모순되는 날씨를 다중 선택으로 조합하지 않습니다.
- 만원 지하철·열차 내부·터널·카페·사무실처럼 밀폐/실내 장면에 비·눈·강풍을 조합해도 실내에 비나 눈이 내리는 식으로 지시하지 않습니다. 강수와 야외 바람은 외부에 유지하고, 창문/개구부로 보이는 외부 움직임과 간접적인 빛·반사 변화만 실내 묘사에 반영합니다. 진행에서 실외↔실내로 바뀌면서 기존 날씨가 계속될 때도 이 관계를 전환 시점에 한 번 명확히 적습니다.
- 배경/날씨 강조는 시간 범위를 가집니다. 시작 상태는 시작 구간에서만, 진행 변경 상태는 그 변경 시점 이후의 해당 구간에서만 명확히 보이도록 지시하며 여러 선택 상태를 영상 전체에 동시에 유지하라고 하지 않습니다. 구조화된 배경/날씨와 자유 입력 scene_prompt가 같은 시간 구간에서 충돌하면 그 구간의 구조화된 선택값이 우선하도록 프롬프트에 명시합니다.
- 짧은 영상에 큰 배경/날씨 변경과 촬영 컷이 과도하게 밀집되면 info에 타임랩스/빠른 환경 전환 위험 경고가 표시됩니다. 또한 완전히 다른 장면/배경 변경이 촬영 컷과 맞지 않은 시점에 발생하면 한 번뿐이어도 배경 모핑·시간압축으로 해석될 수 있음을 별도 경고합니다. 실제 장면 전환 의도라면 해당 시점에 촬영 컷을 맞추는 것이 권장됩니다.
- 문명 붕괴 이후 세계풍(Post-apocalyptic), 사이버펑크, 다크 판타지, 고딕, 몽환적 영상풍은 선택한 배경 자체를 해당 세계관으로 해석합니다. 예를 들어 아포칼립스 놀이공원은 정상 영업 중인 놀이공원을 먼저 지시한 뒤 폐허로 정정하는 방식이 아니라 처음부터 post-collapse 상태의 놀이공원으로 컴파일합니다.
- 구조화된 인물 외형/의상/민족적 외형과 명시적 영상 스타일은 자유 입력 씬 문구와 충돌할 때 구조화된 선택값이 우선하도록 최종 프롬프트에서 명시합니다. 자유 입력 원문 자체를 임의 삭제하거나 재작성하지는 않습니다.
- 자동 환경음은 구조화된 배경/날씨 Timeline을 따라 전환합니다. 과거 카페/도시/해변의 환경음을 이후 장면까지 `continues`로 누적하지 않으며, 발걸음·문·차량처럼 실제 행동과 연결된 동기화 소리는 별도로 유지합니다. 폭우/강풍처럼 강한 환경음이 맑음 등 별도 환경음이 없는 상태로 끝날 때도 이전 비·바람 소리가 남지 않도록 `이전 환경음이 가라앉음` 상태를 시간축에 명시합니다.
- 환경 변화는 장면 전체에 적용됩니다. 진행의 인물 선택은 그 진행에서 행동/대사를 수행하는 대상을 뜻하며, 날씨나 배경이 그 인물 한 명에게만 적용된다는 뜻이 아닙니다.
- 장면·날씨 프리셋은 배경의 사람·차량·조명·입자를 무조건 많이 움직이게 하지 않습니다. 붐비는 장소나 폭풍처럼 움직임이 필요한 경우에도 핵심 움직임만 현실적인 실시간 속도로 표현하며, 진행 중 다른 장소로 바뀔 때는 배경이 타임랩스처럼 가속·변형되지 않도록 새 장면 상태로 전환합니다.
- 환경 프리셋은 기존 촬영 설정과 사운드 설정의 역할을 침범하지 않습니다. 카메라 움직임/구도는 촬영 설정이, 환경음/음악은 사운드가 계속 담당합니다.
- 최종 프롬프트는 단순 태그 나열이 아니라 H3의 시간 순서에 맞는 자연스러운 영상 서술로 조립됩니다. 0초의 실제 시작 상태를 먼저 확정하고, 이후 변화가 발생한 진행 시점에만 배경/날씨 변화를 명시하며 인물 정체성과 진행 중 동작의 연속성을 보존합니다.


[R2V fully_preserved 인물 정체성 충돌 보호]
- 인물 정체성 Reference를 명시적으로 fully_preserved로 지정한 경우 같은 Person의 성별, 나이, 민족적 외형, 외형 프리셋, 외형 추가 입력은 Reference 정체성과 경쟁하는 목표 override이므로 함께 강제하지 않습니다. 명시적 Fully preserved에서는 이유를 표시하고 실행을 차단합니다. Auto 관계에서는 해당 목표 override가 있으면 partially_preserved로 완화하고 `info`에 이유를 남깁니다.
- 인물 의상 Reference의 fully_preserved는 기존처럼 같은 Person의 의상 프리셋/추가 입력과 충돌할 때 같은 원칙을 적용합니다.

[이어 말하기]
- 각 `진행` 그룹에서 `이어 말하기`를 켜면 발화 1 / 발화 2 / 발화 3 블록이 나타납니다.
- 각 발화는 `대사 / 화자 / 언어 / 말하는 방식` 순서입니다.
- 발화 1의 대사·언어·말하는 방식은 해당 진행의 기본 대사 설정을 사용하고, 발화 2/3은 추가 이어 말하기 설정으로 저장됩니다.
- 여러 인물이 말하는 진행은 먼저 `진행 N 대상 인물`을 인물 1+2 또는 인물 1+2+3처럼 실제 화자 범위에 맞춰 설정하십시오.

[입력 자동 보정과 실행 차단]
- 모델의 물리적·구조적 계약을 깨지 않는 단순 설정 실수는 가능한 경우 자동 보정하고 `info` 경고로 알립니다.
- 실제 이미지 연결과 수동 I2V/T2V 모드 불일치, 현재 인원 수와 맞지 않는 화자·촬영 대상, 잘못된 진행·촬영 시작 시간 등은 안전하게 보정 가능한 범위에서 처리합니다.
- R2V의 참조 파일 수·측정 가능한 참조 길이 한도, Audio-only Ref2VA, 손상·과대한 내부 JSON, 예약 H3/R2V 구조 직접 삽입처럼 안전하게 보정할 수 없는 구조 오류는 실행을 차단합니다.
